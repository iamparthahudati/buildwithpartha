### Failure & Recovery UX Architecture & Specification (`55-FAILURE-AND-RECOVERY-UX.md`)

Established comprehensive failure injection verification, honest UX state transitions, non-destructive data retention guarantees, and automated recovery across 8 core failure modes:

1. **Mode 1: Offline Mode & Network Loss**:
   - Persistent top-level offline banner displaying last confirmed sync timestamp.
   - Unsafe remote-only actions (account deletion, password reset) safely disabled with informative tooltips.
   - Core creation items (Brain Dump thoughts, Quick Add tasks, Note drafts) accepted locally into encrypted offline mutation queue with UUID v4 idempotency keys and honest `Queued` status.
   - Automated FIFO queue flushing and status transition (`Queued` $\to$ `Saved`) upon network reconnect.

2. **Mode 2: Network Timeouts & Dropped Packets**:
   - Form inputs (`TaskForm`, `ProjectForm`, `NoteForm`, `HabitForm`, `ReviewForm`) retained in DOM and session draft cache on 504 / client abort.
   - Actionable retry alert with non-blocking "Try again" action.
   - Idempotency key replay ensuring safe idempotency if previous request reached database prior to network drop.

3. **Mode 3: Server 5xx Errors & Service Downtime**:
   - Sanitized RFC 7807 Problem Details (`application/problem+json`) preventing internal stack trace, SQL query, or Java exception leakage.
   - Safe correlation ID presentation (`Reference ID: <correlationId>`) for log correlation without information disclosure.
   - React `ErrorBoundary` containment providing page-level ("Reload page", "Go back") and region-level ("Try again") recovery actions.

4. **Mode 4: HTTP 429 Rate Limiting**:
   - Rate limiting triggers return `Retry-After` header with honest cooldown feedback.
   - Form inputs preserved; submit buttons prevent rapid duplicate multi-clicks.

5. **Mode 5: Expired Authentication & Session Revocation**:
   - In-progress form draft persisted in local storage.
   - Unauthenticated access redirects to `/login?returnTo=<path>`.
   - Post-auth navigation restores destination route and preserves draft.
   - Previous user cached data, queries, and mutation queues purged on account switch.

6. **Mode 6: Stale Version & Optimistic Concurrency Conflicts**:
   - 409 `OPTIMISTIC_LOCK_CONFLICT` error triggers non-destructive conflict prompt ("Keep my changes", "Load server version", "Compare & Merge").
   - Local edits are never silently overwritten or discarded.

7. **Mode 7: Background & Asynchronous Job Failure**:
   - Long-running export and report jobs report explicit `Failed` status badges.
   - Clear failure notice with actionable retry options without blocking application navigation.

8. **Mode 8: Partial Widget Failure & Section Degradation**:
   - Composite Today dashboard isolates failing widget in an inline retryable `Alert` / `ErrorState`.
   - Surrounding healthy widgets (MIT, Today tasks, active sprints, timeline, metrics) continue rendering normally.
