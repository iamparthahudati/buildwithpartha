## Completed behavior

- Added authenticated nested CRUD at `/tasks/{taskId}/comments` and `/projects/{projectId}/comments`: bounded newest-first list, create with `Location`, individual read, optimistic edit, and optimistic permanent delete.
- Every parent and Comment lookup is scoped to the authenticated Account. Missing and cross-user IDs share `404 RESOURCE_NOT_FOUND`; PostgreSQL composite foreign keys also enforce that the Comment Account owns its Task/Project parent.
- All mutations use the existing session-bound `X-CSRF-TOKEN` enforcement. Bodies are non-blank, limited to 4,000 input characters, normalized for line endings, and reject unsafe control characters. Pagination is bounded to 1–100.
- Plain text remains uninterpreted. The Markdown mode escapes raw HTML/entities, flattens inline/reference images, neutralizes reference/shortcut links, preserves only inline HTTP(S) links without userinfo, and flattens malformed/unsafe destinations to their label.
- Active parents permit create/edit. Archived parents remain readable and allow deletion of private content, but reject create/edit as `READ_ONLY`. Updates carry a required body `version`; deletes accept a plain or quoted non-negative `If-Match`; stale mutations return `409 CONCURRENCY_CONFLICT`.
- Delete immediately purges the Comment body and returns `204`; there is no misleading recovery promise. Create/edit/delete transactionally emit body-free `COMMENT_CREATED`/`COMMENT_UPDATED`/`COMMENT_DELETED` Activity Events against the owning Task/Project.
- Task Detail now returns live user-scoped `commentCount` and `activityEventCount` values with a fixed query count as dependency edge volume grows.
