## Goal

Let a task belong to a project milestone so work can be grouped and viewed by phase/milestone,
instead of the label-only workaround. Closes the gap where `tasks` and `milestones` shared no link.

## Design decision — isolated assignment table

The `Task` aggregate record is constructed in 55 places across 18 files (15 test files). Adding a
`milestone_id` component to that record would ripple through every call site and a large share of the
test suite. Instead this ticket models the link as a **separate one-to-one assignment table**
(`public.task_milestones`, PK `task_id`), mirroring how `task_dependencies` is modeled. The `Task`
aggregate is untouched. Trade-off: reads that need a task's milestone make a second lookup rather
than reading a column; acceptable for the current call volume and keeps blast radius minimal.

Invariants (enforced in `TaskMilestoneService`, not the DB):

- The task and the milestone must belong to the **same project**.
- Both must be owned by the **same user**.
- A projectless task cannot be assigned a milestone.
- One milestone per task (enforced by the `task_id` primary key).
- Deleting the task or the milestone clears the link (`ON DELETE CASCADE`).

## Backend (complete, all tests green)

- Migration `V28__task_milestone_assignment_schema.sql` (+ matching table in test `schema.sql`).
- Domain: `TaskMilestoneAssignment`, `TaskMilestoneRepository` (task module).
- Infrastructure: `TaskMilestoneEntity`, `TaskMilestoneJpaRepository`, `JpaTaskMilestoneRepository`.
- Cross-module port: `common/project/MilestoneLookupPort` + `MilestoneReference`, implemented by
  `project/application/DefaultMilestoneLookupPort` (validates ownership via project → user).
- Application: `TaskMilestoneService` (assign / clear / getAssignedMilestone / tasksForMilestone),
  `MilestoneTaskView`.
- API (`TaskMilestoneController`):
  - `PUT /tasks/{taskId}/milestone` — assign (body `{ milestoneId }`).
  - `GET /tasks/{taskId}/milestone` — current assignment (`{ milestone: null }` when unassigned).
  - `DELETE /tasks/{taskId}/milestone` — clear (204).
  - `GET /milestones/{milestoneId}/tasks` — tasks assigned to a milestone.
- Tests: `TaskMilestoneServiceTests` (assign happy path, milestone-not-found, project mismatch,
  projectless task, task-not-found, clear, list, get). Spotless + checkstyle + full `test` green.
