## Completed behavior

Adds `ChartFrame` and `ChartLegend` to `components/navigation/` — the chrome around any chart, placed alongside `MetricCard`/`DataTable`/`PageHeader` per `17-COMPONENT-TO-SCREEN-MAP.md`'s own grouping rather than `components/feedback/`, even though it composes `EmptyState`/`ErrorState` from there.

### `ChartFrame` draws no chart — that stays LOS-0429's ticket

`title`/`titleAction` pass straight through to `Surface` (LOS-0329) rather than reimplementing its landmark wiring; `status` mirrors `DataTable`'s own `"ready" | "loading" | "empty" | "error"` shape (LOS-0424) so the same discriminated-status habit spans both composed data-display components. The actual chart is always the caller's `children` — this ticket's contract, not its rendering.

### Loading state actually announces, not just visually reserves space

`Skeleton`'s own doc comment states: "the waiting state is announced once, by the region's own status text" — `Skeleton` itself is `aria-hidden`. `DataTable`'s own loading rows do not currently do this (checked while building this ticket; noted as a pre-existing gap there, not something this ticket touches). `ChartFrame` renders a `LiveRegion` alongside the skeleton block specifically so `loading` is not silent for a screen-reader user.

### The data-table fallback is a self-contained, uncontrolled toggle

Giving `dataTable` adds a "View as table" button that swaps the chart for that accessible alternative and back — the concrete answer to a chart no screen reader can meaningfully read. It is deliberately uncontrolled: unlike `Tabs`' `selectedId`/`onSelectedIdChange` (justified by a real deep-link use case), there is no cross-component sync need yet for which view is showing, so a single internal boolean is the whole implementation rather than a second controlled prop pair added speculatively.

### `ChartLegend` reuses the eight frozen chart tokens, named output only

`colorName` on each `ChartLegendItem` is a `ColorSwatchName` — the exact type `ColorIconPicker` (LOS-0407) already established for "the eight frozen chart tokens ... named output only." A demo bar visualization and its legend read the same `COLOR_SWATCHES` mapping (or an equivalent local mapping in the chart-frame catalog demo), so the two can never disagree about which color means which series. An item becomes a real `<button aria-pressed>` only when the caller supplies `onToggle` — the same "no handler, no interactive control" split `FormDialog`'s actions and `TimerRing`'s actions already use — otherwise it renders as a plain, non-interactive row.
