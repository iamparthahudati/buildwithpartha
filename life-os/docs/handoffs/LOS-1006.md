## Completed behavior

- Added canonical frontend Week Planner contracts for weekly outcomes, unscheduled Tasks, Product priority/status, day options, allocation values, per-mutation state, and Task filters. The pure filter helper matches Task title or Project text and composes Project and priority filters.
- Built `WeeklyOutcomes` with controlled selection, creation, a server-aligned 20-outcome/200-character boundary, item counts, loading/empty/error/disabled states, and independent Saving/Saved/failed state. Selected outcomes can be reordered with named Move up/Move down buttons or `Alt+ArrowUp`/`Alt+ArrowDown`; drag is never required.
- Built `UnscheduledTaskQueue` over the shared `DataTable`/`FilterBar`. It filters by Task/Project search, Project, and canonical Product priority; renders a semantic table on wide screens and Task cards below 768px; identifies carry-over candidates; and opens an explicit allocation/carry form from each Task.
- Built `TaskAllocationDialog` over `FormDialog` with native day/outcome selectors and bounded planned minutes. Allocate and move require a day; carry-over may remain explicitly unscheduled. The same form is the keyboard and mobile equivalent for future drag-enhanced day planning, preserves values after failure, blocks duplicate pending submission, and restores initial focus to the day selector.
- Added `PlannerMutationStatus` so Task/outcome mutations state Saving, Saved, or the exact recoverable failure. One failed row retains its retry action while confirmed Tasks/outcomes remain visible.
- Added catalog specimens for interactive outcomes, ready/partial-error Task queues, and the move form.
