## Completed behavior

- Implemented user-defined classification labels and task-label attachment capabilities:
  - Database schema: Created `public.task_labels` table migration (`V10__task_labels_schema.sql`) with composite primary key `(task_id, label_id)`, foreign key cascades `ON DELETE CASCADE`, and index `ix_task_labels_label_id`. Updated test schema `schema.sql`.
  - Label CRUD API:
    - `POST /labels` — Create user-owned label with normalized unique name check and color token/hex validation.
    - `GET /labels` — List user's labels.
    - `GET /labels/{id}` — Retrieve label by ID with user isolation.
    - `PUT /labels/{id}` — Update label name/color with optimistic locking (`version`).
    - `DELETE /labels/{id}` — Delete label with optional `replaceWithLabelId` query parameter to reassign project/task labels before deletion.
  - Task-Label Integration:
    - Updated `Task` domain record and `TaskEntity` `@ElementCollection` with `Set<UUID> labelIds`.
    - Added `labelOwnershipValidator` verification in `createTask` and `updateTask` to prevent assigning labels belonging to other users.
    - Integrated `labelId` filter into `GET /tasks` (`TaskQuery`) using JPA criteria builder join.
    - Updated DTOs & Commands: `CreateTaskRequest`, `UpdateTaskRequest`, `CreateTaskCommand`, `UpdateTaskCommand`, `TaskResponse`, `TaskQuery`.
