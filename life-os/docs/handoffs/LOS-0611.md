## Completed behavior

Built the reusable `SprintWeekSummary` feature component for the Today dashboard without moving LOS-0614 screen composition or LOS-0615 API integration into this ticket.

- Sprint and Week are separate named regions with independent loading, empty, error and ready states. A failure in one does not suppress useful or first-use content in the other, and each error can retry independently while retaining its canonical navigation path.
- The current Sprint view shows its localized date range and named point progress through the existing accessible `DonutChart`. Keyboard-readable slices distinguish completed and remaining points, visible prose names the numerator and denominator, and a Sprint with no committed denominator renders explanatory text rather than `0%`.
- The Weekly Plan view renders seven caller-ordered local dates, identifies today with `aria-current="date"`, and gives each day a named Task completion measure. A day with no planned Tasks says `No tasks` instead of presenting a zero-percent judgment.
- Weekly goals and capacity use shared `ProgressBar` primitives with explicit value text. Missing denominators render truthful setup states, and planned time above capacity uses a named warning measure plus neutral explanatory copy rather than color alone.
- Canonical `Open sprint`, `Open Sprints`, and `Open Week Planner` links remain available in the applicable ready, empty and error states.
- The development catalog includes a full ready specimen and a partial-failure/first-use specimen using neutral LifeOS fixtures.
