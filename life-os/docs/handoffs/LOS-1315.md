## Completed behavior

- **Service Worker Shell Caching (`public/sw.js`)**:
  - Implemented versioned static app shell caching (`lifeos-shell-v1`).
  - Pre-caches core app shell resources (`index.html`, `favicon.png`, static bundle assets).
  - Enforces strict security policy: **NO private API responses** (requests matching `/api/` or non-GET methods) are ever cached, bypassing SW cache completely to prevent cross-account/session data leakage.
  - Implemented network-first navigation fallback serving cached `index.html` app shell when offline.
  - Implemented stale-while-revalidate / cache-first static asset handling.
  - Added `SKIP_WAITING` listener for immediate activation upon update confirmation.
- **Frontend Offline Shell Module (`src/features/offline-shell`)**:
  - Implemented `model/serviceWorkerRegistration.ts` with `registerServiceWorker`, `unregisterServiceWorker`, and `clearShellCaches` helpers.
  - Implemented `hooks/useServiceWorkerUpdate.ts` tracking `isUpdateAvailable`, `registration`, `applyUpdate`, and `dismissUpdate`, listening for `controllerchange` to auto-reload on update activation.
  - Implemented `components/UpdatePromptToast.tsx` presenting an accessible alert/toast informing users *"A new version of LifeOS is available."* with an *"Update now"* action.
  - Exposed module via public entrypoint `index.ts`.
- **App & Auth Session Integration**:
  - Integrated `clearShellCaches()` into `AuthSessionProvider.tsx` on logout (`clearSession`) and account switch (`setSession`) to purge static shell caches across user sessions.
  - Mounted `<UpdatePromptToast />` in `AppShell.tsx` overlay root to surface update prompts to signed-in users.
- **Quality & Verification**:
  - Verified 100% test pass rate for `@features/offline-shell` (15 unit tests across 4 test files).
  - Passed `npm run verify:quality` (Prettier, ESLint zero warnings/errors, TypeScript `--noEmit`, module boundary checks, design token checks).
  - Passed `node life-os/scripts/validate-docs.mjs` with zero broken links.
