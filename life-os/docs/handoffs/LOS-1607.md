## Completed behavior

- **Authored Deployment Pipeline Specification (`life-os/docs/41-DEPLOYMENT-PIPELINE.md`)**:
  - Established canonical specification for CI/CD deployment pipeline stages, immutable container tagging conventions, image digest verification, SBOM generation standards, database migration ordering rules, deployment audit record logging, and secret-safe logging redaction rules.
  - Specified 5 pipeline stages: Stage 1 (Build, Test & Scan), Stage 2 (Container Build & SBOM), Stage 3 (Staging Deployment & Automated Smoke Verification), Stage 4 (Manual Release Approval Gate), Stage 5 (Production Deployment & Audit Logging).
  - Defined immutable image tagging policy: primary commit tag (`lifeos-web:<git-sha>`, `lifeos-api:<git-sha>`), release version tag (`lifeos-web:vX.Y.Z`, `lifeos-api:vX.Y.Z`), and sha256 digest verification (`@sha256:...`). Floating tags (`latest`, `dev`, `master`) prohibited.
  - Specified SBOM artifact generation in SPDX and CycloneDX JSON formats via `syft`.
  - Defined pre-rollout Flyway database migration ordering contract guaranteeing zero-downtime schema migrations execute prior to API container rollout.
  - Defined JSON deployment audit record format (`/var/log/life-os/deployments.json`).
  - Established secret redaction principles guaranteeing zero credential, token, or password exposure in deployment logs.

- **Created Automated Deployment Pipeline Script (`life-os/scripts/deploy-pipeline.sh`)**:
  - Executable shell script supporting `--target=staging|production`, `--tag=<sha-or-version>`, `--dry-run`, `--skip-smoke`.
  - Handles environment pre-flight validation, container build/pull reference generation, pre-rollout Flyway migration ordering check, compose service rolling restart, smoke test verification, secret redaction, and deployment audit record creation.

- **Created Declarative GitHub Actions Deployment Workflow (`.github/workflows/lifeos-deploy.yml`)**:
  - Defined multi-stage deployment workflow with jobs: `LifeOS / Build, Test & Scan`, `LifeOS / Container Build & SBOM`, `LifeOS / Deploy Staging`, and `LifeOS / Deploy Production`.
  - Configured GitHub protected deployment environments for `staging` and `production` with manual approval requirement on production release tags.
  - Enforced least-privilege workflow permissions (`contents: read`, `packages: write`) and commit SHA-pinned GitHub Actions.
