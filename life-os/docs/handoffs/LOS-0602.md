## Completed behavior

Implemented the shell's top utility bar component for LifeOS per `docs/backlog/EPIC-06-SHELL-TODAY.md`, `docs/23-NAVIGATION-AND-ROUTES.md`, `docs/22-INFORMATION-ARCHITECTURE.md`, and `docs/wireframes/02-SHELL-TODAY.md`. Like `Sidebar` (LOS-0601), this ticket builds only the component — self-contained, catalog-registered, independently testable — not the app shell that mounts it (LOS-0603), the Quick Add dialog (LOS-0604), the real focus mini-player (LOS-0605), or the full Search/Notifications screens.

- **Component (`apps/web/src/components/navigation/TopBar.tsx`)**:
  - Layout order per the wireframe: context label/date → Search trigger → Quick Add trigger → Notifications → focus slot → AccountMenu.
  - Every action item is a caller-controlled trigger: TopBar renders no `CommandPalette`, no notification list, and no focus UI of its own. `onSearchTriggerClick`, `onQuickAddTriggerClick`, and `onNotificationsTriggerClick` are the only integration points.
  - Date/context computed internally from required `timeZone`/`locale` props via the canonical `todayLocalDate`/`formatLocalDate` helpers (`lib/localDateTime.ts`) — never raw `Intl.DateTimeFormat().resolvedOptions()` or `new Date()`, matching `DateRangeField`'s existing precedent.
  - Global search shortcut wired through `useCommandPaletteShortcut` (Cmd/Ctrl+K), suppressible via `searchShortcutEnabled`.
  - `notificationCount` drives a `CountBadge` on the bell (clamped, always announces the real count).
  - `focusSlot?: ReactNode` is a caller-owned slot for LOS-0605's future mini-player; TopBar renders nothing by default.
  - `account: AccountMenuProps` composes `AccountMenu` (LOS-0415) as-is.
  - Root is a bare `<header>` outside `<main>` so it is the page's one `banner` landmark; renders no skip link (Sidebar already owns the app's single skip link).

- **Responsive overflow ("adapts without hiding essential mobile actions")**:
  - Context label, Search, and Quick Add stay visible at every width — the essential mobile actions.
  - Below 768px, the formatted date, Notifications, `focusSlot`, and AccountMenu collapse behind a single "More" trigger into a `Drawer` — the same dual-render, hide-one-of-two-copies pattern `FilterBar` (LOS-0420) already uses, needed here (rather than `Menu`) because the overflow content includes `AccountMenu`, an already-interactive popover-owning widget that cannot legally nest inside another `Menu`'s ARIA menuitem list.
  - Overflow trigger carries `aria-expanded`/`aria-haspopup="dialog"`, wired by hand (neither `Drawer` nor `FilterBar` set these today). Drawer content order matches the inline row's left-to-right order.

- **Tokens (`apps/web/src/styles/tokens.css`)**:
  - Added `--lifeos-layout-topbar-height: 3.5rem`, matching `Sidebar`'s own header block. Reuses `--lifeos-z-navigation` for the sticky header.

- **Styling (`apps/web/src/components/navigation/top-bar.css`)**:
  - Strict `--lifeos-*` semantic tokens only. `@media (width < 768px)` breakpoint mirrors `filter-bar.css`'s literal-px convention.

- **Tests (`apps/web/src/components/navigation/TopBar.test.tsx`)**:
  - 12 test cases, 0 axe violations across default, notifications, focus-slot, and overflow-open states. Covers: banner landmark and trigger accessible names, date formatting from a fixed `timeZone`/`locale`/`now`, unread badge presence/absence and clamping, Cmd/Ctrl+K firing (and its suppression), overflow drawer open/close with `aria-expanded`/`aria-haspopup`, content order matching the inline row, and focus restoring to the trigger on close.

- **Catalog Demos & Registry (`apps/web/src/catalog/`)**:
  - `TopBarDemo`: default desktop row with live callback logging.
  - `TopBarWithNotificationsDemo`: unread count clamped to "99+".
  - `TopBarWithFocusSlotDemo`: caller-supplied `StatusDot` in the focus slot.
  - `TopBarOverflowOpenDemo`: same composition, documented for resizing below 768px.
  - Registered under "Composed" group in `navigationEntries.tsx`.
  - A live-browser check of all four states (desktop and a real 375px viewport) caught one real bug: the first `TopBarDemo` wrapper used `overflow: hidden` for a rounded-card look, which silently clipped `AccountMenu`'s `position: absolute` popover — not a `TopBar` defect, but a demo-styling one, fixed by dropping `overflow: hidden` from the shared demo stage style.

- **Module Public Entrypoint (`apps/web/src/components/navigation/index.ts`)**:
  - Added `TopBar`, `TopBarProps`.
