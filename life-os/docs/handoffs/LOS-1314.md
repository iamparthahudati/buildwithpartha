## Completed behavior

- **Created Conflict Resolution Domain Module (`src/features/conflict-resolution`)**:
  - Implemented `model/conflictContract.ts` defining standard `ConflictDetails` and `FieldDiff` contracts, field label humanization (`formatFieldLabel`), value formatting (`formatFieldValue`), field-by-field payload comparison (`comparePayloadFields`), and formatted clipboard backup text builder (`buildConflictCopyText`).
  - Implemented `hooks/useConflictResolution.ts` managing conflict modal lifecycle state, local payload/server payload state, clipboard copy actions, and explicit resolution choice callbacks (`useServer`, `overwriteLocal`).
  - Implemented `components/ConflictResolutionBanner.tsx` displaying inline warning alerts (`role="alert"`) with actions for Compare Changes, Use Server Version, and Overwrite Server.
  - Implemented `components/ConflictResolutionModal.tsx` providing a full accessibility-compliant side-by-side field comparison table, difference highlighting, copy-to-clipboard backup button, and version selection actions.
  - Implemented `components/QueuedConflictResolver.tsx` providing specialized resolution dialog for offline mutation queue items that failed replay due to HTTP 409 conflicts, allowing users to inspect payloads, copy JSON, retry replay, or discard items.
  - Exposed domain module through public entrypoint `index.ts`.
- **Integrated Conflict Resolution into Offline Mutation Queue (`OfflineQueueBadge.tsx`)**:
  - Updated `OfflineQueueBadge` to accept `conflictCount` and `onResolveConflicts` props, displaying a `warning` tone badge with 409 conflict count and a `Resolve conflict` action button.
- **Added Catalog Entries (`composedEntries.tsx`)**:
  - Added interactive specimens for `ConflictResolutionBanner` and `ConflictResolutionModal` to the design system catalog.
