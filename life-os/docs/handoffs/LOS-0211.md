## Completed behavior

Added fail-fast environment validation to both application entry points. Vite validates the public application/API paths before development or production build startup and the browser bootstrap validates the compiled public values again. Spring validates required runtime keys before service or persistence beans are created, then binds the public URL, cookie policy and sender into typed configuration.

Missing and blank values are reported together. Path, JDBC URL, HTTP URL, port, boolean and mail-address shapes are rejected where applicable. Every failure reports key names only; tests use sensitive-looking inputs to prove values are not reproduced.

## Files and contracts changed

- Added the typed frontend environment boundary and focused Vitest coverage.
- Made the Vite base/API proxy derive from validated public configuration.
- Added deterministic Vite `test` mode configuration and a self-contained `build:test` command.
- Added the backend application-context initializer, typed Spring properties and focused JUnit coverage.
- Removed backend runtime connection defaults so non-test startup cannot silently use local credentials.
- Clarified required versus optional keys in safe local `.env.example` files and documented the startup contract.

## Database/config/deployment changes

- No dependency, lockfile, database, migration, provider, browser storage, container, VPS, Cloudflare or production deployment change.
- Normal frontend development/production startup now requires copied/exported public values from `apps/web/.env.example`.
- Normal API startup now requires every non-empty key from `apps/api/.env.example`; SMTP username/password remain optional for the local mail catcher.
- Tests remain deterministic and require no external secret or service.
