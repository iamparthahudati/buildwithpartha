## Completed behavior

Added the token-driven CSS reset and global foundations that every later component builds on. `global.css` now layers deliberately: tokens define the values, the reset normalizes browser defaults, and the application rules apply the LifeOS canvas on top. A test enforces that order, because a reset loaded after the application rules would silently undo them.

The reset normalizes what browsers disagree about and nothing else. Box sizing is inherited, default margins are removed so vertical rhythm stays explicit in components, form controls inherit typography instead of falling back to the OS font, media cannot overflow its container, and `[hidden]` is authoritative. Native semantics are deliberately preserved: list markers are kept, because removing them globally strips list semantics in some screen reader and browser combinations; heading levels, control roles and native focus behavior are untouched; and the root font size stays at `100%` so the user's browser text-size setting continues to work. `reset.css` declares no color literal.

Accessibility hooks are now application-wide rather than per component. A single `:focus-visible` rule supplies the ring for keyboard users, and the only permitted suppression is `:focus:not(:focus-visible)` — components override the ring's shape, never its existence. Under `prefers-reduced-motion: reduce` a backstop neutralizes animation, transition and smooth scrolling even for styles that do not read the motion tokens, and smooth scrolling is opt-in behind `no-preference`. Under `forced-colors: active` the user's palette wins: the focus ring switches to `CanvasText`, shadows are dropped since they carry no meaning there, and icons follow the surrounding text. `prefers-contrast: more` promotes the two quietest tokens so hairline separators and muted text survive.

The skip link is the first tab stop on the page. It is moved off-screen with a transform rather than `display: none` or `visibility: hidden`, so it stays focusable and reveals itself on focus, and it sits on the `--lifeos-z-skip-link` layer so nothing can cover it. It targets a `tabindex="-1"` main landmark, which moves real focus rather than only the scroll position while keeping the landmark out of the tab order.

## Known limitations or follow-ups

- The preference hooks are asserted by parsing the stylesheet, because JSDOM has no layout engine and does not evaluate `forced-colors`, `prefers-contrast` or rendered focus rings. Real forced-colors and reduced-motion behavior still needs browser verification at LOS-0332.
- The skip link currently lives in `App.tsx` with a global class. When the app shell ticket introduces real navigation it should move into the shell, and the class should become a component; the `tabindex="-1"` landmark contract must survive that move.
- `.foundation` styles remain the temporary readiness view and are replaced by the app shell ticket.
- Increased contrast is handled through `prefers-contrast: more` only; no separate user-facing contrast setting exists.
