## Completed behavior

Fixed a cross-cutting identity/settings defect surfaced during the first live end-to-end run of the app against a real backend (the LOS-0615 Today integration made the shell reachable end to end for the first time). Every prior test of these screens ran against a mocked `fetch`, which never exposed it.

- **React Query mutation result handling.** The call-time callback form — `mutation.mutate(vars, { onSuccess, onError })` — did not fire reliably against the real backend, so post-submit navigation, toasts, and error surfacing silently never ran. Every such site was converted to the promise form `mutation.mutateAsync(vars).then(...).catch(...)`. Reactive mutation state (`isPending`, `isSuccess`, `error`) was already correct and unaffected; only the one-off call-time callbacks were broken. Converted sites:
  - `ForgotPasswordScreen` (`forgotPasswordMutation`)
  - `LoginScreen` (`loginMutation`)
  - `ResetPasswordScreen` (`resetPasswordMutation`)
  - `SignupScreen` (`signupMutation` — success already read reactively; only the error path was on a call-time callback)
  - `VerifyEmailScreen` (`verifyMutation` auto-verify effect and `resendMutation`)
  - `AccountDeletionCancelScreen` (`cancelMutation`)
  - `ProfileSettingsPanel` and `LocalizationSettingsPanel` (`updateProfileMutation` / preferences)
  - `PrivacySettingsPanel` (`requestExportMutation`, `deleteAccountMutation`)
  - `SecuritySettingsPanel` (profile/password mutations)
  - Bare fire-and-forget `.mutate()` calls that pass no callback object (`logout`, `revokeSessionMutation`, `revokeOtherSessionsMutation`, focus `completeMutation`, onboarding `logoutMutation`) were correctly left as-is — they are unaffected by the defect because they rely on reactive state, not call-time callbacks.
- **Post-login navigation preserves the in-memory session.** `LoginRoute` now passes the router's client-side `navigate` into `LoginScreen`, overriding the screen's default `window.location.assign` (chosen when it was built because no router existed yet). Per `06-SECURITY.md` the session lives only in memory and there is no `GET /auth/session` endpoint, so a full-page navigation immediately after login tears down the app — discarding the session `useLogin`'s success just set — and the user lands logged out. Staying client-side keeps the freshly set session alive to render the protected route.
- **Local dev preview config.** `.claude/launch.json` now attaches the preview to the running dev server URL (`http://127.0.0.1:5173`) instead of launching `npm run dev` itself. Dev-only; no product behavior.

## Known limitations or follow-ups

- The reliable pattern for these screens is `mutateAsync().then().catch()`; new mutation call sites that need post-submit side effects should follow it rather than the call-time callback form.
- The root cause (why the call-time callbacks did not fire against the real backend while reactive state did) was addressed at the call-site level, not investigated to a library/version root cause. If it recurs, capture it against a real backend rather than a mocked `fetch`.
