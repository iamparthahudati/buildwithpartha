## LOS-0315 — PasswordInput

Composed from the same markup as `TextInput` rather than wrapping it, because the reveal toggle has to sit inside the control's focus ring and needs its own state.

Revealing works by switching `type` between `password` and `text`. That is also why the toggle **returns to concealed on every mount**: a revealed field has left password-manager territory, and a component that remembered the revealed state across mounts would expose a value the user only meant to check once. The toggle carries `aria-pressed`, so assistive technology knows whether the value is currently visible.

`autoComplete` is restricted by the type signature to `new-password` or `current-password`. Getting this wrong is the single most common reason password managers stop offering to generate or fill, so it is a deliberate choice rather than a free-form string.

The Caps Lock hint is announced through `role="status"` — politely, because it describes what is happening now rather than a validation failure, and it must not interrupt typing.

The `help` slot takes a strength meter or policy list but **receives no value**. Anything derived from the password is computed by the caller, so this component has no path by which it could leak it.

## LOS-0316 — Textarea

Auto-growing uses the `field-sizing: content` CSS property rather than measuring `scrollHeight` in JavaScript. The JavaScript approach costs a layout read on every keystroke and has to be re-run whenever the value changes from outside the component; the CSS property has neither problem, and browsers without support keep the fixed `rows`, which is a graceful loss rather than a break.

The character counter counts **code points**, so an emoji counts as one character rather than two. It deliberately does not set `maxLength` on the element: silently truncating a paste loses the user's text without telling them. Instead the counter turns red, `aria-invalid` is set, and validation decides. The number itself is hidden from assistive technology, because announcing it on every keystroke would be unbearable.

Horizontal resize is disabled because it breaks responsive layouts; vertical resize stays available.

## Known limitations or follow-ups

- The Caps Lock hint only updates on `keyup` inside the field, so it cannot know the state before the user starts typing, and it does not clear when focus leaves. Both are inherent to `getModifierState` and acceptable for a hint.
- `field-sizing` is not supported everywhere yet. Unsupported browsers fall back to fixed rows with vertical resize, which is usable but not the intended behaviour; worth re-checking at LOS-0332.
- The character counter requires a controlled `value`; an uncontrolled textarea shows `0`.
- Password strength scoring is out of scope — the `help` slot is the seam for it when a real sign-up screen needs one.
