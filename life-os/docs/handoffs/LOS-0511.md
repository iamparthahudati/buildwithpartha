## Completed behavior

Implemented the verification screens and lifecycle states covering all requirements of the acceptance contract: `Sent`, `resend cooldown`, `verifying`, `verified`, `invalid/expired` and `already-used` states; no email enumeration; accessible recovery actions.

- **Backend resend verification endpoint**:
  - Implemented `POST /life-os/api/v1/auth/resend-verification` (`ResendVerificationService`, `ResendVerificationCommand`, `ResendVerificationRequest`, `ResendVerificationResponse`, `AuthController`, `ApiSecurityConfiguration`).
  - Added `ResendVerificationRateLimiter` port and in-memory implementation (`InMemoryResendVerificationRateLimiter`, 5 attempts / 15 minutes per IP/email).
  - Enqueues `EMAIL_VERIFICATION` outbox email transactionally if the account exists and is `UNVERIFIED` (minting a new 24h verification token), safely logs audit event `AUTH_EMAIL_VERIFICATION_RESENT`, and returns `202 ACCEPTED` with `{"status": "PENDING_VERIFICATION"}` unconditionally for anti-enumeration.
- **Frontend API client & mutation hooks**:
  - Added `resendVerification` API client method in `features/auth/api/authApi.ts` (+ tests in `authApi.test.ts`).
  - Added `useVerifyEmail` (`POST /auth/verify-email`) and `useResendVerification` (`POST /auth/resend-verification`) mutation hooks (+ tests).
- **Verification Screen (`VerifyEmailScreen`)**:
  - **`verifying` state**: Renders when a token is provided (via prop or `?token=` query param). Auto-triggers verification on mount, displaying an accessible `Spinner` (`aria-live="polite"`), heading "Verifying your email", and status text.
  - **`verified` state**: Rendered on successful verification. Displays "Email verified" heading, confirmation text, and primary "Sign in" button navigating to `/life-os/login`.
  - **`expired` state**: Rendered when backend returns `TOKEN_EXPIRED` (400). Displays warning alert, security explanation of 24h TTL, and an accessible resend action (with cooldown if email is known, or a button to enter email).
  - **`invalid` state**: Rendered when backend returns `TOKEN_INVALID` (400). Displays danger alert, recovery action to request a new link, and sign in/signup links.
  - **`already-used` state**: Rendered when backend returns `TOKEN_ALREADY_USED` (409). Displays information that the link was already consumed, a direct "Sign in" primary button, and a secondary action to request a new link.
  - **`sent` state**: Rendered when verification email is dispatched. Displays "Check your email", instructions, spam folder hint, and active 60-second cooldown timer on the resend button (`Resend email (59s)` -> disabled, then enabled when 0).
  - **`request` state**: Rendered when navigating without a token or known email. Provides an accessible email input form with client validation, `FormErrorSummary` focus management, and submission to resend verification.
  - **Error handling**: `429 RATE_LIMITED` renders `"Too many attempts. Wait a few minutes before trying again."` and unexpected errors render generic alert messages with auto-focus.
- **Accessibility & styling**:
  - Mobile-first single-column layout in `verify-email-screen.css` adhering strictly to design token scales.
  - Passes WCAG 2.2 AA accessibility audits with 0 violations across all verification states.
