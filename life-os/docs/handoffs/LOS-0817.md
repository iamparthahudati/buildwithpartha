## Completed behavior

- Built `SchedulingPanel` as the reusable Task Details scheduling and focus feature component named by `docs/17-COMPONENT-TO-SCREEN-MAP.md`.
- Shows confirmed Time spent derived from Focus Sessions, including an honest `Not recorded` state that stays distinct from a confirmed zero-minute value.
- Renders linked Time Blocks through the existing `TimeBlockRow` contract, including localized wall-clock ranges, status, current state, and named overlap details.
- Exposes Schedule at the panel header when Time Blocks exist and inside the first-use empty state when none are linked. Scheduling, retry, and conflict-resolution behavior stays caller-controlled for the shared scheduling service.
- Offers Start focus for the Task and each eligible linked Time Block. Both paths share one guarded request funnel, expose target-specific pending state, prevent parallel starts, and show safe recovery copy without claiming time was recorded.
- Consumes the shared Focus Session projection instead of creating duplicate focus state. An active session for this Task replaces all Start focus actions with one Open focus action; an active session for another Task names the conflict without exposing private data beyond the caller-supplied safe projection.
- Covers loading, first-use empty, region error/retry, permission read-only, temporarily disabled/offline-style, blocked, archived/deleted/terminal, schedule conflict, active session, pending, and partial schedule/focus failure states. No destructive action belongs to this panel.
- Keeps confirmed schedule/time visible during permission, disabled, active-session, conflict, and partial-failure states. Blocked Tasks may still be scheduled but cannot start focus until blockers are resolved; terminal or archived/deleted Tasks cannot mutate schedule or start focus.
- Added catalog specimens for ready, conflict, active Focus Session, empty, read-only, load-error, and loading states.
