## Completed behavior

Froze the LifeOS design tokens as a two-layer contract. A private `--palette-*` layer holds the literal colors and may only be declared and read inside `styles/tokens.css`; a semantic `--lifeos-*` layer names the role each value plays and is the only layer components consume. The frozen set covers semantic color, typography, spacing, radius, border, shadow, z-index, motion, breakpoint, density and chart tokens.

Accessibility is proven rather than asserted. `CONTRAST_REQUIREMENTS` enumerates every pairing the design system is allowed to render with its WCAG 2.2 AA minimum and its usage; the test suite computes the real contrast ratio for each one. Three initial palette targets failed and were corrected: the solid status fills were darkened so white labels reach 4.5:1, the warning accent moved from `#f79009` to `#dc6803` to reach 3:1, and the interactive control border moved to `#7d8b9f` so input outlines reach 3:1. A pairing that is not listed has not been proven and must not be used.

Zoom, motion and touch guarantees are enforced by tests rather than convention: every font size, spacing and radius token is declared in `rem` so 200% zoom and browser text scaling both work, no font size drops below the 12px floor, every non-zero motion duration is redefined to `0ms` under `prefers-reduced-motion: reduce`, and compact density is overridden on coarse pointers so touch targets stay at 44px.

`npm run verify:tokens` is now part of the required frontend quality gate and fails the build when any file outside the token file contains a raw hex, `rgb()`, `hsl()` or `color()` value, sets a color property to a named CSS color, or reads the private palette layer. `global.css` was rewritten to consume tokens only, so the rule holds across the existing source tree today rather than starting from a grandfathered exception.

## Known limitations or follow-ups

- Contrast is proven by computing ratios from the frozen values, which is exact for solid pairings but does not cover text rendered over the `--lifeos-color-overlay` scrim or over a gradient. Those cases need browser verification when the components that use them exist.
- Axe cannot check color contrast under JSDOM because it has no layout engine, so rendered-contrast and 200% zoom still need browser automation and manual review at the atom accessibility audit (LOS-0332).
- Tokens are light-theme only, matching current scope. The two-layer structure means a theme would remap the semantic layer without renaming tokens, but no dark or forced-colors palette is defined; forced-colors hooks belong to LOS-0302.
- The verifier scans `src/`; `index.html` and files outside the source root are not covered.
