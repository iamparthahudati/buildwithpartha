## Completed behavior

### Performance Budgets & Benchmarks Specification (`54-PERFORMANCE-BUDGETS-AND-BENCHMARKS.md`)

Established enforceable performance budgets, latency SLAs, resource utilization boundaries, and automated regression testing across the LifeOS stack:
1. **Frontend Asset & Bundle Budgets**:
   - Initial entry JS (`index.js`) budget $\le 200\text{ kB}$ raw (actual: ~21 kB).
   - Combined initial JS payload budget $\le 350\text{ kB}$ raw (actual: ~258 kB across vendor and entry).
   - CSS bundle budget $\le 50\text{ kB}$ raw (actual: ~22 kB).
   - Per-route chunk budget $\le 100\text{ kB}$ raw (actual: ~2–25 kB).
   - Zero Rollup `chunkSizeWarningLimit` overrides required.
2. **Frontend Dynamic Code-Splitting Architecture**:
   - Extracted all 30 route components into `src/app/routeLoaders.ts` dynamic import factories.
   - Refactored `src/app/AppRouter.tsx` to load routes via `React.lazy` wrapped with `<Suspense fallback={null}>`.
   - Configured Rollup `manualChunks` in `vite.config.ts` separating `vendor-icons` (`lucide-react`), `vendor-query` (`@tanstack/react-query`), and `vendor-react` (`react`, `react-dom`, `react-router-dom`).
   - Reduced single monolith JS bundle from 1.16 MB to an ultra-light ~21 kB initial shell.
3. **Core Web Vitals (CWV) & Real-User Monitoring**:
   - Defined target and budget thresholds: LCP $\le 1500\text{ ms}$, INP $\le 100\text{ ms}$, CLS $\le 0.05$, FCP $\le 1000\text{ ms}$, TTFB $\le 400\text{ ms}$.
   - Created client-side utility module `src/lib/performance.ts` with `evaluateMetric`, `formatMetricValue`, `captureNavigationTimings`, and `observePerformanceMetrics`.
   - Full Vitest unit test coverage with mock PerformanceObservers in `src/lib/performance.test.ts`.
4. **Backend API Latency SLAs (p95)**:
   - Tier 1 (Fast/Health/Profile): $\le 100\text{ ms}$ p95 target.
   - Tier 2 (Standard Entity CRUD): $\le 250\text{ ms}$ p95 target.
   - Tier 3 (Multi-Domain Aggregations): $\le 500\text{ ms}$ p95 target.
5. **Database Query Performance & Connection Pool**:
   - Single-query execution budget $\le 50\text{ ms}$.
   - HikariCP pool configuration (10 max connections, 5 min idle, 30s timeout).
   - Index verification on foreign keys and tenant isolation columns (`user_id`).
6. **Container & System Resource Budgets**:
   - API container: 512 MB memory reservation / 1024 MB limit; 0.5 CPU reservation / 1.0 CPU limit; JVM `-XX:MaxRAMPercentage=75.0`.
   - Web container: 64 MB memory reservation / 128 MB limit; 0.1 CPU reservation / 0.25 CPU limit.
   - Database container: 256 MB memory reservation / 512 MB limit; `shared_buffers = 128MB`.
7. **Large-Data Volume Scalability**:
   - 50+ task batch retrieval within sub-second execution window.
   - 100+ habit log entries and 365-day streak calculation within sub-second execution window.
   - JVM heap stability bounds ($\le 512\text{ MB}$ peak test heap).
