## Shared groundwork

Four controls arriving at once made the duplication in the form atoms impossible to keep ignoring: label wiring, description, error and success were being rebuilt per control, and every one of those relationships fails silently when it breaks — a description that is not referenced is simply never announced.

`Field` (`components/ui/Field.tsx`) now owns that frame. The control itself is passed as `children`, so each component keeps its own native element and behaviour; only the wiring is shared. `field.css` grew the shell classes (`.lifeos-field__control`, `.lifeos-field__element`, `.lifeos-field__affix`) that the four new controls sit inside.

`TextInput`, `PasswordInput` and `Textarea` predate `Field` and still carry their own copy of the frame. Migrating them is recorded as an audit item for LOS-0331 rather than done here, because their tickets are closed and the change is a refactor rather than a fix.

`.lifeos-visually-hidden` moved out of `button.css` into its own `visually-hidden.css`. It was previously only present when a `Button` happened to be on the page, so any screen rendering a `Select` and nothing else would have painted its "hidden" label. Every consumer now imports the stylesheet directly. LOS-0327 adds the component on top of it.

## LOS-0318 and LOS-0319 — the date and time value boundary

`lib/localDateTime.ts` is new, and is the only place allowed to turn an instant into a date-only or time-only value, or to format one.

A due date is a calendar date, not an instant. The moment `2026-08-17` goes through a `Date` in the browser's zone it acquires a time of day, and a user whose confirmed timezone differs from their browser's starts seeing their deadline land on the day before or after. So date-only and time-only values are carried as `YYYY-MM-DD` and `HH:mm` strings from the input to the API and back, and `DateInput`/`TimeInput` never parse them.

- `todayLocalDate(timeZone, now)` answers "what is today" from the user's confirmed IANA timezone rather than the browser clock. It assembles the result from named `Intl` parts, so it does not depend on how a locale happens to order or punctuate a date.
- `addLocalDays` uses `Date.UTC` purely as a calendar engine — parts in, parts out, no zone conversion — so a day containing a daylight-saving change is still one day.
- `formatLocalDate` pins the formatter to UTC, because the value was placed into UTC parts with no zone attached; letting it fall back to the browser zone is exactly the off-by-one this module exists to prevent.

## LOS-0317 — Select

A real `<select>`. A custom listbox would have to re-implement type-ahead, Home/End, PageUp/PageDown and the platform's touch picker, and would still not be the control the user's device knows how to render. Nothing in the v1 scope needs option grouping with icons, multi-select or async search, so the custom listbox stays deferred, as the ticket allows.

The placeholder option is the one real decision: it stays **selectable on an optional field**, so a user can take an answer back, and is **disabled on a required one**, because "no answer" is not one of the answers. `multiple` is removed from the prop type — a multi-select list is unusable on touch and invisible about how to select more than one thing; a set of Checkboxes says the same thing honestly.

## LOS-0320 — NumberInput

Scrolling the page over a focused number field silently changes its value in most browsers, and the user's next glance finds an estimate they never entered. The usual fix is to `blur()` the field, which costs the user their place and fires blur validation. This one registers a non-passive `wheel` listener directly on the element and prevents the default only while the field is focused — React attaches wheel listeners passively at the root, so `onWheel` cannot do it. Page scrolling over an idle field is untouched.

The unit is announced rather than hidden: a number read aloud without its unit means nothing, so the unit carries an id that joins `aria-describedby` instead of being `aria-hidden` like a decorative affix. The value itself stays canonical — `.` decimal, no grouping — because a field that reformats while it is being typed into fights the user; localized display belongs at the display boundary.

Native spin buttons are kept. They are user-agent controls, which WCAG 2.2 target size (2.5.8) exempts, and removing them would take away the only pointer affordance for stepping a value.

## Known limitations or follow-ups

- `readOnly` on `type="date"` and `type="time"` is unreliable across browsers — several still open the picker. Use `disabled`, or render the value as text, until LOS-0332 confirms the current behaviour.
- Native date and time fields cannot be styled beyond their picker indicator, so they will not match `TextInput` pixel for pixel. That is the price of the platform picker and is recorded for the LOS-0331 visual audit.
- `Select` supports a flat option list only. Grouped options (`<optgroup>`) are unimplemented until a screen needs them.
- `TextInput`, `PasswordInput` and `Textarea` have not been migrated onto `Field`; queued for LOS-0331.
