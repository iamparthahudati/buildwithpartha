## Completed behavior

Composed and integrated the full Brain Dump experience (LOS-1207), completing the
capture → inbox → triage → conversion loop built across LOS-1204–LOS-1206 and
closing the one remaining acceptance gap: **offline draft/queue integration**.

Capture, the inbox list, search/status/archived filters, and single + batch
conversion were already wired end-to-end by LOS-1205/LOS-1206. Before this
ticket, however, a capture made while offline was **dropped** — the route set an
"offline-queued" label but never persisted or replayed the text, so anything
typed offline was lost on reload. LOS-1207 makes that promise real:

- **Persistent offline queue**: Captures made while `navigator.onLine` is false
  are written to `localStorage`, namespaced per user
  (`lifeos.brain-dump.capture-queue.<userId>`), so nothing is lost across page
  reloads and one account's drafts never leak to another on a shared browser.
- **Automatic flush on reconnect**: When connectivity returns (or on mount with a
  leftover queue), the queue flushes in FIFO order, sending each capture and
  removing it from persistence on success. A capture that fails to send is
  **retained** and the flush stops at the first failure, so a flaky reconnect
  never drops a thought and never hammers a still-unreachable API.
- **Visible, actionable queue**: A `role="status"` banner in the capture section
  shows the pending count ("N captures waiting to sync…" / "— you are offline"),
  a **Sync now** button (enabled only when online), and a **Discard** button.
  The route reports the flush outcome via toast (all synced, or "X synced, Y
  still queued").
- **Storage resilience**: Every `localStorage` access is guarded — a private
  window, disabled storage, corrupt JSON, or a quota error degrades to an
  in-memory no-op / empty queue instead of throwing into the capture path.

## Files and contracts changed

### Brain Dump feature (`apps/web/src/features/brain-dump/*`)
- `model/captureQueue.ts` (new) — `localStorage`-backed, per-user queue helpers:
  `readCaptureQueue`, `writeCaptureQueue`, `enqueueCapture` (trims, ignores
  blanks, stamps `queuedAt`, generates a stable id), `removeQueuedCapture`,
  `clearCaptureQueue`, and the `QueuedCapture` type. All storage access guarded.
- `hooks/useBrainDumpCaptureQueue.ts` (new) — owns the queue lifecycle:
  rehydrates on mount/user-change, exposes `enqueue`/`flush`/`discardAll`,
  `queuedItems`/`queuedCount`/`isFlushing`, and a `FlushResult` (`sent`/
  `remaining`). Auto-flushes on reconnect (guarded against overlapping flushes
  via a ref), invalidating Brain Dump + activity queries when anything sent.
- `components/BrainDumpScreen.tsx` (+ `.css`) — new props `queuedCount`,
  `flushing`, `onFlushQueue`, `onDiscardQueued`; renders the offline queue banner
  under the capture bar.
- `index.ts` — exports the new hook and queue model.

### Routing
- `routes/BrainDumpRoute.tsx` — wires `useBrainDumpCaptureQueue`; `handleCapture`
  now enqueues (instead of dropping) when offline; adds `handleFlushQueue`
  (toast on outcome) and `handleDiscardQueued`; passes the queue props to the
  screen.

## Known limitations or follow-ups

- **Offline queue is for capture only.** Deep offline queueing of *conversions*
  and other mutations remains deferred to the global offline-sync phase, as noted
  in LOS-1205/LOS-1206.
- The `model/captureQueue.ts` name reflects the module-boundary allowlist
  (`api`/`components`/`hooks`/`model`/`test` only); it is the persistence model
  for the offline queue despite touching `localStorage`.
- **Pre-existing projects regression still open** — `ProjectsRoute.test.tsx`
  failure from commit `2146278` belongs under a Projects (LOS-07xx) ticket.
