## Completed behavior

- **Server/Client Approach ADR (ADR-014)**:
  - Created a new Architectural Decision Record [ADR-014](../adr/ADR-014-PDF-REPORT-EXPORT-APPROACH.md) detailing options and drivers for PDF report export.
  - Selected the **client-side print layout approach** (`window.print()`) over server-side PDF generation. This preserves strict user privacy (zero report files are stored, transmitted, or cached on the server, avoiding any leakage or expiry concerns), maintains rendering fidelity of SVG/canvas charts, and avoids server-side CPU/memory overhead or java dependency lock changes.
  - Logged the decision in the global [10-DECISIONS.md](../10-DECISIONS.md).
- **Accessible & Print-Tested Layout**:
  - Implemented a print-only metadata header block (`.reports-screen__print-header`) in the reports screen.
  - This header displays Report Type, Date Range, Timezone, and active Project/Category filters. Since the interactive controls and filters sidebar are hidden in print view, this print-only block guarantees that the exported PDF contains the complete report parameters.
  - Hidden in screen view (`display: none`) and displayed only during printing (`display: block`).
- **Page Breaks**:
  - Refined `@media print` CSS rules in `reports-screen.css` to prevent awkward splitting of visual components.
  - Applied CSS page-break avoidance (`break-inside: avoid` / `page-break-inside: avoid`) on major report widgets, including the Narrative Summary Box, Summary Metrics grids, Charts, and Tabular Data sections.
- **Privacy & Security**:
  - Confirmed zero backend file storage or token expiry modifications are needed, as all generation and saving are handled in browser memory.
  - Hidden screen-only interface elements (sidebar, top navigation bar, filters selector bar, actions header, and action buttons) to prevent them from cluttering the PDF.
