## Completed behavior

Implemented the account recovery screens (`ForgotPasswordScreen` and `ResetPasswordScreen`) fulfilling all requirements of the acceptance contract: forgot and reset forms preserve safe user input, handle missing, expired, already-used, and invalid tokens, validate password policy, display session revocation notice upon reset, and support seamless return to login.

- **Frontend API client & mutation hooks**:
  - Added `forgotPassword` (`POST /auth/forgot-password`) and `resetPassword` (`POST /auth/reset-password`) client functions in `features/auth/api/authApi.ts` (+ tests in `authApi.test.ts`).
  - Added `useForgotPassword` and `useResetPassword` mutation hooks in `features/auth/hooks/` (+ comprehensive unit tests).
- **Validation & field error models**:
  - `forgotPasswordValidation.ts` & `forgotPasswordFieldErrors.ts`: Client-side validation of email shape and length bounds with approved tone guide copy; maps backend validation problem details.
  - `resetPasswordValidation.ts` & `resetPasswordFieldErrors.ts`: Client-side validation of `newPassword` length (`MIN_LENGTH: 12`, `MAX_LENGTH: 128`), `confirmPassword` equality, and maps server-side password policy violation codes (`TOO_SHORT`, `TOO_LONG`, `COMMONLY_EXPOSED`).
- **Forgot Password Screen (`ForgotPasswordScreen`)**:
  - **`form` state**: Email input form, client validation, callback-ref focus management via `FormErrorSummary`, submit action calling `useForgotPassword`, link to Sign in (`/life-os/login`).
  - **`sent` state**: Displays "Check your email" with generic message: `"If an account matches that email, we've sent password reset instructions. The link expires in 1 hour."`, return to sign in action, and link to re-enter a different email address.
  - Preserves entered email across submissions and errors.
  - Rate limiting (`429 RATE_LIMITED`) and unexpected failure handling.
- **Reset Password Screen (`ResetPasswordScreen`)**:
  - Resolves token from prop or `?token=` query param.
  - **`missing-token` state**: Rendered when no token is present; displays warning alert and action button navigating to `/life-os/forgot-password`.
  - **`form` state**: Renders `newPassword` and `confirmPassword` (`PasswordInput`, `autoComplete="new-password"`), password policy guidance (`"Use at least 12 characters."`), client and server validation. Preserves user input without burning the token if password policy fails on the backend.
  - **`expired` state**: Rendered on `TOKEN_EXPIRED` (400) from backend; explains 1-hour expiration with action to request a new link.
  - **`already-used` state**: Rendered on `TOKEN_ALREADY_USED` (409); explains link consumption with primary action to sign in and secondary action to request a new reset link.
  - **`invalid` state**: Rendered on `TOKEN_INVALID` (400); displays danger alert with action to request a new reset link.
  - **`success` state**: Rendered on successful password reset; announces explicit session revocation: `"Your password has been changed. For your security, all active sessions on all devices have been signed out. Please sign in with your new password."` with primary "Sign in" action.
  - Rate limit handling and focus management on error alerts.
- **Accessibility & styling**:
  - Mobile-first layout in `recovery-screen.css` adhering strictly to design token scales.
  - Passes WCAG 2.2 AA accessibility audits with 0 violations across all screen states.
