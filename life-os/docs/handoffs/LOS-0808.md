## Completed behavior

- Added authenticated, CSRF-protected `POST /tasks/bulk-actions` with a bounded selection of 1–100 unique Task IDs.
- Supports `STATUS`, `PRIORITY`, `PROJECT`, `ADD_LABEL`, `REMOVE_LABEL`, `SCHEDULE`, `CLEAR_SCHEDULE`, and `ARCHIVE`. In this Task contract, schedule sets or clears the canonical `dueAt` UTC instant; future Time Block linkage remains outside this ticket.
- Validates action-specific request fields before mutation and returns normal Problem Details for invalid selections, duplicate IDs, missing parameters, and unsupported actions.
- Processes every selected Task in its own transaction. Successful items remain committed when another item is missing, cross-user, invalid, or concurrently changed.
- Returns a stable ordered partial-result contract with requested/succeeded/failed counts and one `SUCCEEDED` Task representation or safe `FAILED` error code per requested ID.
- Preserves user isolation for Task IDs and re-authorizes Project and Label targets without coupling product-domain packages. Archived Projects are not accepted as new Task destinations.
- Makes retry naturally idempotent: status, priority, Project, Label, schedule, clear-schedule, and archive actions return the unchanged current Task when the requested state is already applied, without advancing its version.
- Preserves existing status semantics: `DONE` sets progress to 100, terminal states clear MIT, and terminal blockers continue to trigger dependent-task unblocking.
