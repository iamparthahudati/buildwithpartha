## LOS-0304 — Icon primitive

`Icon` is the single wrapper around the approved icon set. Consumers import the specific Lucide icon and pass the **component itself** rather than naming it through a string map, because a string map would pull every icon into the bundle and defeat tree-shaking.

Sizes are named (`sm`/`md`/`lg`/`xl`) and applied as classes backed by rem tokens, not as the library's pixel `size` prop, so icons scale with the user's text settings and at 200% zoom. The library is passed `size="100%"` specifically to stop it stamping a fixed 24px box.

Accessibility is decided by the type signature, not by convention: an icon is either `decorative` (hidden from assistive technology, because adjacent text carries the meaning) or carries a `label` (exposed as a named image). One of the two is always required.

The icon set decision, its licence and the dependency-policy deviation are recorded in [ADR-013](../adr/ADR-013-ICON-SET.md).

## LOS-0305 — Typography primitives

`Heading`, `Text`, `Caption`, `Metric` and `TruncatedText`.

Visual size and semantic level are separate props on `Heading`. Coupling them is the most common way heading outlines degrade — an author who needs a smaller-looking heading reaches for a deeper level — so `level` sets the element and `size` sets the appearance independently.

`numeric` opts into tabular numerals, required wherever a value changes in place (durations, timers, metrics, dates) so digits do not shift width. `Metric` pairs a value with a **visible** label element rather than a `title` or `aria-label`, so the label is readable, translatable and selectable like any other text.

`TruncatedText` clips to a line budget visually while leaving the complete string in the DOM, so screen readers and find-in-page still reach all of it; the `title` attribute lets a pointer user recover the rest but is never the only route to it.

## LOS-0306 — Button

A real `<button>` in five variants (primary, secondary, ghost, danger, link) and three sizes, with decorative icon slots at either end. `type` defaults to `button` so a button inside a form cannot submit it by accident.

The loading state is the substantive part. A loading button uses `aria-disabled` rather than the `disabled` attribute, so it **stays focusable** and the user is not silently dropped out of the tab order mid-interaction; activation is blocked in the handler, which is what actually prevents a duplicate submit. The label stays in the DOM and is only hidden visually, so the button keeps its width and the surrounding layout does not jump. `aria-busy` and a visually hidden loading label carry the state to assistive technology, so nothing depends on the spinner animation — which stops entirely under reduced motion.

The `link` variant looks like a link but is still a button, because it performs an action rather than navigating. Real navigation belongs to `Link` (LOS-0308).

## LOS-0307 — IconButton

An icon-only control composed from `Button`. `label` is a **required** prop, so an icon-only control without an accessible name is a type error rather than something review has to catch. The icon is passed as decorative and the control carries the name — this is the rule LOS-0304 deferred here.

The label is rendered visually hidden rather than omitted, so text content survives a stylesheet failure. `title` repeats the label for pointer users and can be suppressed with `showTitle={false}` once the real Tooltip (LOS-0326) takes over. Targets grow to 44px on coarse pointers at every size, which matters more here than anywhere else because there is no text to enlarge the hit area.

## Known limitations or follow-ups

- Adding a dependency inside a feature ticket deviates from the LOS-0203 rule that lockfile changes belong to a dedicated update ticket. ADR-013 records why this ticket is the exception; it should not become a precedent.
- The danger variant's hover uses a `filter: brightness()` step rather than a dedicated token. If a hover state for danger is wanted long term, it deserves its own token so contrast is proven rather than computed at render time.
- `.lifeos-visually-hidden` currently lives in `button.css`. It moves to the shared helper when LOS-0327 lands.
- Tooltip integration for `IconButton` is the native `title` for now; LOS-0326 replaces it.
- Focus, contrast and touch targets are asserted structurally and through axe, which cannot evaluate rendered contrast under JSDOM. Browser verification remains at LOS-0332.
