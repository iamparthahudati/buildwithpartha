## Completed behavior

- **Notifications & Notification Preferences REST API (`/notifications`)**:
  - Implemented authenticated, user-scoped in-app notification center REST API with domain model and full JPA persistence.
  - Exposes `GET /notifications` supporting pagination (`page`, `size`), `unreadOnly` filter, and multi-category filtering (`category`, `categories`).
  - Exposes `GET /notifications/unread-count` returning current total unread notifications for the active user.
  - Exposes `PUT /notifications/{id}/read` and `PUT /notifications/{id}/unread` to toggle notification read state.
  - Exposes `PUT /notifications/read-all` to bulk mark all unread notifications read in a single transactional query.
  - Exposes `DELETE /notifications/{id}` to clear a single clearable notification. Attempting to clear a non-clearable notification (such as `SECURITY` notices) throws `NotificationNotClearableException` returning `400 BAD_REQUEST` with error code `NOTIFICATION_NOT_CLEARABLE`.
  - Exposes `DELETE /notifications` to bulk clear all clearable notifications for the active user.
  - Exposes `GET /notifications/preferences` and `PUT /notifications/preferences` for user-level quiet hours (`quietHoursStart`, `quietHoursEnd` in `HH:mm` format with regex validation), category toggle preferences, and channel toggles (in-app, email, push). Default preferences (quiet hours `22:00`-`07:00`, all categories enabled, in-app channel enabled) are auto-provisioned upon first fetch or update.
  - Implemented `NotificationRetentionJob` running daily scheduled cleanup (`@Scheduled(cron = "0 30 4 * * *")`) to purge clearable notifications older than 90 days (R5 retention policy).
  - Implemented `[REDACTED]` in `toString()` overrides for `Notification` aggregate root and `NotificationResponse` DTO to guarantee private notification titles and bodies are never logged.
