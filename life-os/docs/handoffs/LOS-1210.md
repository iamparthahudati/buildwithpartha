## Completed behavior

Defined the canonical habit/streak calculation specification for LifeOS Epic 12.

### Canonical specification (`docs/34-HABIT-STREAK-CALCULATIONS.md`)

Documents all deterministic rules required by LOS-1210:

- **Period grid by cadence**: DAILY — each local date is one period; WEEKLY — ISO weeks (Mon–Sun); MONTHLY — calendar months. Periods at window edges are clipped to the requested `[from, to]` range.
- **Pause exclusion**: a period is paused (and invisible to the streak counter) when *every* calendar day in it is covered by at least one `HabitPausePeriod`. Paused periods neither extend nor break streaks. Partly-paused periods remain eligible; only recorded entries count toward the target.
- **Target evaluation**: sum of `completedCount` across all entries whose `localDate` falls within the period ≥ `habit.targetCount`. Multiple entries on the same local date are summed (covers repeated increment calls).
- **Current streak**: scan eligible periods from last to first; stop at the first miss. A paused period is skipped without breaking the count.
- **Longest streak**: forward scan; running counter resets to 0 on a miss.
- **Late-edit semantics**: backdated entries are stored with their specified `localDate` and repair streaks retroactively. This is intentional.
- **Timezone-change semantics**: entries store the local date resolved at recording time using the then-current timezone; changing the habit's timezone later does *not* re-bucket stored local dates.
- **Rounding**: `completionRate = (double) metTargetPeriods / eligiblePeriods`; raw Java double; `0.0` when `eligiblePeriods == 0`.
- **Boundary cases table**: empty window, all-paused, single period met/unmet, last period paused, open-ended pause.
- **Governance**: rule changes require updating this document, the calculator Javadoc, and the fixture tests.

### Domain classes

- `HabitStreakCalculator.java` — pure stateless domain service (no Spring annotations, no dependencies beyond the habit domain). Accepts `Habit`, `List<HabitEntry>`, `List<HabitPausePeriod>`, `from`, `to` and returns `HabitStreakResult`. Entries outside the window are silently ignored.
- `HabitStreakResult.java` — record with `currentStreak`, `longestStreak`, `eligiblePeriods`, `metTargetPeriods`, `completionRate`; validates non-negative counts and rate in `[0.0, 1.0]` in its compact constructor.

## Known limitations or follow-ups

- `HabitStreakCalculator` is not yet wired into any REST endpoint or service — it is a pure domain service ready for LOS-1211 (Build habit components) and LOS-1212 (Compose and integrate Habits) to delegate streak display to.
- The LOS-1209 `GET /habits/{habitId}/stats` endpoint returns a plain window projection without pause-aware eligibility. A future ticket (most naturally LOS-1212) should expose pause-aware streak values from `HabitStreakCalculator` via a dedicated endpoint or augment the stats response.
- Specific weekday schedules (e.g. Mon/Wed/Fri only) are not modeled in the cadence enum; this is a deferred concern noted in LOS-1208 and is not in LOS-1210 scope.
- The pre-existing Brain Dump Spotless/Checkstyle gate failures and two Today/Brain Dump test regressions remain on `develop` and are unrelated to this ticket.
