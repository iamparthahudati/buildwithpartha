## Completed behavior

Modeled habits, habit entries, and habit pause periods (LOS-1208) — the data slice
that Epic 12's habits work (LOS-1209 API, LOS-1210 streak calculations, LOS-1211+
UI) builds on. This ticket delivers the schema, domain aggregates, and persistence
ports only; no REST API, service, or UI is in scope here (that is LOS-1209).

The acceptance contract — *"Habit/cadence/reminder/entry schema with local date,
target count, pause periods, uniqueness/version and timezone-safe streak
invariants"* — is satisfied as follows:

- **Cadence + target count**: `habits.cadence_type` (`DAILY`/`WEEKLY`/`MONTHLY`,
  CHECK-constrained) with a per-period `target_count` (CHECK `> 0`, e.g. eight
  glasses of water a day, three runs a week).
- **Reminder preference**: `reminder_enabled` + optional `reminder_time` (local
  time-of-day). A DB CHECK and a domain invariant both require a `reminder_time`
  whenever reminders are enabled.
- **Timezone-safe streaks**: each habit carries an IANA `time_zone` (validated via
  `ZoneId.of` in the domain constructor). `Habit.localDateFor(Instant)` buckets a
  completion instant into the habit's own local calendar date, so streaks stay
  deterministic across timezone changes and near-midnight completions. Entries
  store that resolved `local_date` (a `DATE`, not a timestamp).
- **Entry uniqueness**: `habit_entries` is unique on `(habit_id, local_date)` — one
  row per habit per local day; a second completion on the same day increments
  `completed_count` (CHECK `> 0`) rather than inserting a duplicate.
- **Pause periods**: `habit_pause_periods` holds inclusive `[start_date, end_date]`
  ranges (open-ended when `end_date` is null) with a CHECK that `end_date >=
  start_date`; `HabitPausePeriod.covers(LocalDate)` answers eligibility for the
  streak rules to be authored in LOS-1210.
- **Optimistic concurrency**: `habits` and `habit_entries` carry a `@Version`
  `version` column. (Pause periods are immutable append/delete records and omit it.)

## Known limitations or follow-ups

- **Pre-existing backend gate breakage (not LOS-1208).** `spotlessApply` and
  `checkstyleMain` both report violations on brain-dump files committed under
  LOS-1204/1206/1207 (`braindump/**`, `common/braindump/**`, and the
  `BrainDump*CreatorAdapter` classes in goal/note/task) — long single-line
  constructor calls that exceed google-java-format's 100-column rule. These were
  left untouched here; a whole-tree `spotlessCheck`/`checkstyleMain` therefore
  fails independently of this ticket. Worth a dedicated formatting-fix ticket.
- **Cadence is coarse** (`DAILY`/`WEEKLY`/`MONTHLY` + target count). Specific
  weekday schedules (e.g. Mon/Wed/Fri) are intentionally deferred; the enum and
  `target_count` cover the Epic-12 acceptance contract and can be extended without
  a breaking migration.
- **Streak/eligibility math is not implemented here** — `covers()` and
  `localDateFor()` provide the timezone-safe primitives; the full cadence
  eligibility / late-edit / missed-day rules and deterministic fixtures are
  LOS-1210.
