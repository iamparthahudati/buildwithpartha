## Completed behavior

Added the development-only component catalog: the surface where every component and every one of its states is visible at once, at any supported viewport.

Entries are **registered** rather than discovered. A registry that scans the filesystem hides an omission; an explicit registry makes a missing state visible, which is the whole point of a catalog that later serves as the completeness check for the design system. `assertRegistryIsValid` fails loudly on a duplicate entry id, a duplicate state id within an entry, or an entry that registers no states, and it runs on every render rather than only in a test.

Viewport controls constrain the specimen stage. The presets deliberately start at the 320px minimum rather than at a desktop width, because responsive problems appear there first; the remaining presets follow the frozen breakpoints, plus a fluid option that follows the browser window. The stage width is applied through a `--catalog-stage-width` custom property so the width rule stays in CSS and the component only supplies the value.

The catalog is seeded with the foundations that exist today — color roles, the type scale and tabular numerals, spacing and radius, elevation and the stacking contract, and motion durations. Atoms register themselves from LOS-0304 onward.

### Production exclusion

The ticket allows excluding or protecting the catalog. This implements **exclusion**, because an artifact that was never built cannot be reached, guessed at, or left enabled by a misconfigured environment variable — whereas a runtime check is only as good as the configuration behind it.

`vite.config.ts` now names `index.html` as its only Rollup input, so `catalog.html` is never an input and no catalog module reaches `dist/`. `src/catalog/main.tsx` additionally refuses to mount unless `import.meta.env.DEV`, as a second line of defense if the entry is ever bundled by mistake. A Node test asserts all three facts and scans the built output for any catalog artifact or reference.

The catalog is served by the dev server only, at `/life-os/catalog.html`.

## Known limitations or follow-ups

- The catalog has no router, so entry selection is component state and is not addressable by URL. Deep links to an entry or state should arrive with the routing ticket.
- Viewport controls resize the stage inside the page rather than rendering into an iframe, so a specimen still sees the real window for media queries. Container queries or an iframe stage would make breakpoint behavior fully faithful; that matters once atoms carry their own responsive rules.
- Specimen states are rendered but not visually regression-tested. Visual comparison is LOS-0331's scope.
- `catalog.html` is reachable in development without authentication, which is intentional for a local tool but means the dev server should not be exposed beyond loopback. It is already bound to `127.0.0.1`.
