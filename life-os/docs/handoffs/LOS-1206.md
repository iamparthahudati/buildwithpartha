## Completed behavior

Built the Brain Dump **conversion workflow** on the frontend (LOS-1206), turning the one-tap
convert stubs from LOS-1205 into a real, contract-correct workflow.

- **Destination preview / fields**: A new `BrainDumpConvertDialog` lets the user pick a destination
  (Task / Note / Project / Goal) and edit the destination-specific fields, pre-filled from the
  captured text (title/name derived from the first line; note body defaulted to the full content;
  task/project priority `P3`; goal category `PERSONAL`, progress type `BINARY`, cadence `WEEKLY`).
  Each row's four convert buttons open the dialog pre-selected to that destination.
- **Preserve source**: The original captured text is shown in the dialog and never mutated — the
  Brain Dump item is retained (status becomes `CONVERTED`), not deleted.
- **Transactional result link**: On success the dialog shows a link to the created entity
  (`/life-os/app/{tasks|notes|projects|goals}/{id}`), read from the response
  `convertedToType`/`convertedToId`. An item that is already converted opens straight to its result
  link.
- **Retry after timeout without duplicates**: Conversion sends the item `version`; the backend
  short-circuits on already-`CONVERTED` items **before** the version check (LOS-1204), so retrying
  after a timeout returns the existing entity instead of creating a duplicate. A failed conversion
  keeps the item unchanged and surfaces an inline, retry-safe error.
- **Partial batch results**: A batch-selection checkbox on each eligible row plus a batch bar
  ("N selected → Convert to …") convert many items to one destination via `Promise.allSettled`, so
  each item succeeds or fails independently. `BrainDumpBatchResultDialog` reports the per-item
  outcome, links every success, and offers a safe retry of only the failures.

### Contract correction (important)

LOS-1205's convert client sent only `{ title }` / `{ name }` and no `version`, which would have
**400'd** against the real LOS-1204 endpoints. LOS-1206 corrects the frontend convert contract to
match the backend: required `priority` (task/project), `body` (note), `category`/`progressType`/
`checkInCadence` (goal), and `version` on every convert; and maps the previously-dropped response
fields `convertedToType`, `convertedToId`, `convertedAt`, `archivedAt` (with `archived` now derived
from `archivedAt`).
