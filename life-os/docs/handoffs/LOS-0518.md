## Completed behavior

Implemented account deletion lifecycle conforming to `02-ARCHITECTURE.md`, `05-API-CONVENTIONS.md`, `06-SECURITY.md`, `31-PRIVACY-DATA-LIFECYCLE.md`, and `docs/backlog/EPIC-05-IDENTITY.md`:

- **Re-Authentication & Confirmation**:
  - `AccountDeletionRequest`: Requires current password and explicit account name or email confirmation matching the authenticated user.
  - Re-authenticates password against Argon2id hash before processing deletion.
- **Immediate Data & Session Lifecycle**:
  - `AccountDeletionService`: Revokes all active user sessions immediately across all devices.
  - Enqueues security alert email via `TransactionalMailPort` notifying the user of account deletion.
  - Enqueues `ACCOUNT_DELETION` background job for downstream asynchronous purges via `BackgroundJobPort`.
  - Executes cascading purge of the user row in `public.users` (with database `ON DELETE CASCADE` removing credentials, sessions, tokens, preferences, and export files).
  - Emits security audit log without logging sensitive credentials or personal text.
- **Background Job Execution (`AccountDeletionJobHandler`)**:
  - Registered `@JobHandlerFor(BackgroundJobKind.ACCOUNT_DELETION)` handler for asynchronous audit/cleanup processing.
- **REST Endpoint (`SecurityController`)**:
  - `POST /auth/account/delete`: Authenticated, CSRF-protected deletion endpoint. Clears `lifeos_session` cookie in response and returns `AccountDeletionResponse`.
