## Completed behavior

- Added authenticated `GET /reports/time?date={localDate}&timeZone={ianaZone}` with private/no-store caching. The response supplies completed focus/break minutes, unscheduled completed focus, personal Time Block minutes, category allocation, planned Focus Time Block minutes, the optional daily target, active-session state, comparison source/minutes, percentage, and an explicit `hasData` value.
- Converts a requested Account-local date into start-inclusive/end-exclusive instants. DST-short and DST-long days retain their real duration, while overnight Time Blocks are clipped exactly to the selected day.
- Uses non-cancelled Time Blocks whose category is case-insensitively `Focus` as the preferred denominator. When no planned focus minutes exist, it falls back to the optional Account daily target. With neither, comparison minutes and percentage remain null; actual time may truthfully exceed 100%.
- Counts confirmed whole focus/break minutes from Completed Focus Sessions only and excludes Cancelled sessions. Each terminal session is attributed to the Account-local date containing its canonical `startedAt`; an active session is exposed separately and never added to confirmed actual totals.
- Replaced the Time Blocks screen's fixed demo summary with the canonical report query. Focus/break/personal/unscheduled metrics, category allocation, and the progress card now reflect server data and label whether the denominator is planned focus or the daily target.
- Replaced the Today focus provider's zero-only adapter with the same aggregation and extended its response with target/comparison source/progress fields while preserving the existing planned/actual fields.
- Added the optional daily target to Focus settings, including set, clear, 1–1,440-minute validation, complete-payload preservation, and direct navigation from the Time Blocks setup/edit action.
- Time Block mutations and every Focus Session state transition that changes reportable state invalidate the daily report query as well as the existing Today/Calendar/Time Block projections.

## Known limitations or follow-ups

- Daily actuals use deterministic Focus Session start-date attribution because the current aggregate stores accumulated phase totals rather than a per-phase interval ledger. A Focus Session crossing local midnight is therefore reported on the day it started; this rule is now explicit in the API and Today calculation contracts.
- The daily target is one Account preference applied as fallback on every date; there is no per-date target history. A planned Focus Time Block always takes precedence for that date so the denominator represents explicit scheduling.
- LOS-0917 exposes one daily report. Metric dictionary versioning plus range/project/label/category report filters remain LOS-1105/LOS-1106 and must reuse, not redefine, this daily calculation.
