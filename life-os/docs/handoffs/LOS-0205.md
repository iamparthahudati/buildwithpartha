## Completed behavior

Established the first forward-only LifeOS Flyway contract. Flyway records checksums in `lifeos_internal.lifeos_schema_history`, while future product objects remain in `public`. Automatic baselining, schema creation and Flyway clean are disabled so an incorrect or non-empty target fails safely rather than being silently accepted or erased.

The V1 migration enables only PostgreSQL's trusted `pgcrypto` extension. It does not create Account data or any product-domain table before the owning domain tickets.

Local database initialization now creates a dedicated non-superuser migrator role in addition to the restricted runtime application role. The migrator owns the private history schema and grants runtime access to future public tables through scoped default privileges. The API role cannot read Flyway history or create databases, schemas, roles or replication resources.

- Database migration: `V1__initialize_schema.sql`; forward-only and transactional on PostgreSQL.
- Persistent metadata: private Flyway history table plus the `pgcrypto` extension; no user or product content.
- Configuration: separate optional `FLYWAY_DATABASE_*` values, private history schema and safe migration switches.
- No production database, user data, VPS, Cloudflare or deployment resource changed.
