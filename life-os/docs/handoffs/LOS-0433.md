## Completed behavior

Adds `ActivityFeed` to `components/navigation/` — structured actor/action/object/time rendering, grouped pagination, a safe fallback for a deleted object, and decorative accessible icons.

### Actor/action/object stay three separate slots, never one sentence

`ActivityEvent` carries `actorName`, `action` (a past-tense verb phrase) and an optional `object` as distinct fields rather than a pre-formatted string — the same "no domain hardcoded" principle `FilterBar`/`DataTable` already apply to their own caller-supplied slots. This component has no idea what actions a Task or a Project can have; it only knows how to lay out whichever triple it is given.

### A deleted object gets a safe fallback, never a broken link

`object` is `undefined` for a deleted or otherwise inaccessible record. Rather than a dead link or omitting the row, it renders plain, non-linked "a deleted item" text — `docs/30-CONTENT-AND-TONE-GUIDE.md`'s own "state unavailability without leaking existence" rule, the identical reasoning `EmptyState`'s `permission` variant and the "Not found/private" error copy already apply elsewhere.

### Real nested lists for day-grouping, no ARIA workaround needed

Events group into `Today`/`Yesterday`/a real localized date via a new `activityGrouping.ts`, each group rendered as its own `<li>` containing a day label and a nested `<ul>` of event rows. A plain list tolerates this nesting natively — unlike `CommandPalette`'s `role="listbox"` grouping (LOS-0426), which needed `role="presentation"` throughout specifically because ARIA's listbox pattern forbids non-option children. `Pagination` (LOS-0421) composes below exactly like `DataTable` already does: paging decides which page of events is loaded, grouping is a pure presentation split of whichever page that is.

### `todayLocalDate` answers "what day is this instant" for any instant, not only the real now

`activityGrouping.ts` calls `todayLocalDate(timeZone, new Date(event.createdAt))` for every event — that function (LOS-0318) already accepts an arbitrary `Date`, so passing each event's own timestamp through it is exactly the UTC-instant-to-viewer's-calendar-day conversion grouping needs, with no new date-math module required.

### Every icon is decorative

The actor/action/object text already carries the complete meaning, so a caller-supplied icon per event only reinforces it — the same rule `Badge`/`StatusDot` (LOS-0309) already state for color never carrying meaning alone. Omitted entirely when a caller doesn't supply one, the same optional-marker convention `Timeline`'s (LOS-0430) `STATUS_ICON` already uses.

### Timestamps are reused, not reimplemented

Both the relative visible string and the full absolute accessible-label string come directly from `commentTimestamp.ts` (LOS-0432) — nothing about that formatting was ever comment-specific, so there was nothing to duplicate.

### A real bug the live-browser pass caught

The loading skeleton's bars rendered at `0px` width: `SkeletonText`'s bars are percentage-widthed against their parent, but `.lifeos-activity-feed__event` is a row flex container, and a flex-row child with no `flex`/`width` of its own sizes to its content — empty, for a skeleton with no text — collapsing the percentage to zero against a zero-width box. Confirmed via `getBoundingClientRect()` showing a real `0` before the fix. `CommentList`'s identical-looking loading skeleton never hit this because its row is a *column* flex, where children stretch to full width by default; `ActivityFeed`'s row layout needed an explicit `flex: 1` on the loading skeleton specifically, scoped so it doesn't affect the real event row's own icon/sentence/time children. Confirmed after the fix via the same `getBoundingClientRect()` check and visually in both desktop and a 375px mobile screenshot.

## Known limitations or follow-ups

- No infinite-scroll variant — the ticket names "grouped pagination" specifically, and `Pagination`'s own page-number UI is what's composed; a screen wanting infinite scroll would need its own separate composition, the same way `DataTable`'s own `Pagination` slot works today.
- `object` is currently all-or-nothing (a full label+href pair, or entirely absent). A record the viewer can see but not open (named but not linked) isn't a case this ticket's wording named, and would need its own explicit third state if a future screen needs it.
