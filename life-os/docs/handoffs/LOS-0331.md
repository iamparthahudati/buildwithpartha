# LOS-0331 handoff

- Status: Done
- Branch: `feature/LOS-0331-atom-audits-gate`
- Date: 2026-08-17

## Scope

LOS-0331 compares every atom shipped in Epic 03 (LOS-0303–LOS-0330) against the token contract in `docs/32-DESIGN-TOKENS.md` and the principles in `docs/03-DESIGN-SYSTEM.md`, and records intentional differences from the supplied visual references. It does not touch behaviour or accessibility semantics — that is LOS-0332.

## Method

- `npm run verify:tokens` re-run against the full source tree: every component still consumes only `--lifeos-*` semantic tokens, and only `styles/tokens.css` reads the private `--palette-*` layer. No raw color literal exists anywhere else.
- Every registered catalog entry was read against its component source to confirm the specimen set actually exercises the states the ticket promised (default/error/disabled at minimum, plus the component's own special states).
- Every stylesheet under `components/ui/` was scanned for a class selector with no live consumer, and every component was scanned for a class name with no matching stylesheet rule.
- Cross-component duplication was compared against the shared primitives introduced in LOS-0317 (`Field`) and LOS-0323 (`Spinner`), since those are the two seams this phase deliberately created for later components to reuse.

## Findings and fixes

**The three form controls shipped before `Field` existed did not use it.** `TextInput`, `PasswordInput` and `Textarea` (LOS-0314–LOS-0316) each carried their own copy of the label/description/error/success wiring, predating the shared frame `Field` introduced in LOS-0317. Left alone, the codebase would have carried two ways to build the same relationship, and the next control to imitate one instead of the other. Fixed: all three now render through `Field`; `text-input.css` is deleted, and `field.css`/`textarea.css` carry only what remains component-specific. Their public props and rendered DOM structure are unchanged — this was verified by the pre-existing `formControls.test.tsx` and `dataEntry.test.tsx` suites passing unmodified.

**`Button`'s loading indicator duplicated `Spinner`.** `button.css` had its own `.lifeos-button__spinner` keyframe and reduced-motion override, built before LOS-0323 existed. Fixed: `Button` now renders `Spinner` directly, inheriting the button's own color and font size; the duplicate CSS is removed.

**A duplicate accessible-name bug surfaced during the `Button`/`Spinner` merge.** Before this fix, a loading button's name fell back to its hidden loading text once the visible label was marked `aria-hidden`, so a screen-reader user heard "Saving" instead of "Save changes" — losing exactly the information they need while waiting on the button. Fixed with `aria-labelledby` pinned to the (still-present, only visually hidden) label span; a new test (`Button.test.tsx`) asserts the accessible name stays the button's own label while loading, and that the busy text is separately available through `role="status"`. This is a correctness fix uncovered by the audit, not a pre-existing regression from this ticket's other changes — recorded here because LOS-0331/0332 is where it was caught.

**Catalog completeness.** All 27 atom entries from LOS-0304 through LOS-0330 are registered (Radio + RadioGroup, Badge + StatusDot + CountBadge, VisuallyHidden + LiveRegion, and DividerList + DividerListItem count as one entry each, matching how their tickets shipped them together). No entry has zero states; `assertRegistryIsValid` continues to fail loudly if that ever changes.

**No orphaned CSS.** No stylesheet class lacks a component consumer and no component class lacks a stylesheet rule, checked by grep across `components/ui/*.css` and `components/ui/*.tsx`.

## Intentional differences from the supplied visual references

Recorded once here rather than per component, since the same three choices repeat throughout Epic 03:

- Every reference name, fixture and copy string is LifeOS-original (`Portfolio refresh`, `Prepare weekly review`, etc.); no reference-product identity, wording or data reached source, tests or fixtures.
- Native form elements (`Select`, `DateInput`, `TimeInput`) render the platform's own picker chrome rather than a custom-drawn one, per the LOS-0317 "native first" direction — this is a deliberate accessibility trade-off, not a visual gap to close later.
- Every animated or gradient-drawn component (`ProgressBar`, `ProgressRing`, `Spinner`, `Skeleton`, `Tooltip`) has an explicit `forced-colors` fallback, which the references do not need to define since they are static mockups.

## Files and contracts changed

- `TextInput.tsx`, `PasswordInput.tsx`, `Textarea.tsx` rewritten to compose `Field`; `text-input.css` deleted; `field.css` and `textarea.css` trimmed to component-specific rules.
- `Button.tsx` now renders `Spinner`; `button.css` loses its duplicate spinner keyframe.
- `Button.test.tsx` gains a name-stability test and a busy-status test.

## Validation performed

- The pre-existing `formControls.test.tsx`, `dataEntry.test.tsx`, `feedback.test.tsx` and `structure.test.tsx` suites all pass unmodified against the refactored components, confirming their public contracts did not change.
