## Completed behavior

Composed the complete Today screen from the already completed LOS-0608–LOS-0613 feature components, without moving LOS-0615 API integration into this ticket.

- `TodayScreen` accepts the header/metric, plan, Next up, schedule, Daily Review, Sprint/Week, active Projects, and Brain Dump component contracts as independently controlled props. It does not duplicate or flatten their state models.
- The component's semantic source order follows the documented narrow-screen priority: make the daily decision, see what is next, check the schedule, review the day, then move into Sprint/Week, Project, and capture context.
- Tablet uses a two-column grid while keeping plan, schedule, and Sprint/Week full width. Desktop uses a 12-column grid with the daily plan and schedule receiving the most space. No breakpoint changes DOM order.
- An offline notice names the caller-provided last update time and distinguishes unavailable server actions from explicitly supported device drafts. An overloaded notice offers `Review plan` and states that nothing was automatically rescheduled or reprioritized.
- Widget-level errors remain inside their owning regions. The partial-failure specimen proves failed Tasks, scheduled-time metric, and active Projects do not suppress the selected MIT, schedule, Review, Sprint/Week, or Brain Dump capture.
- The catalog registers five complete screen specimens: first use, normal, overloaded, partial failure, and offline. The shared viewport control exercises all five at the 320px minimum, tablet, desktop, and fluid sizes.
- `/life-os/app/today` now mounts `TodayScreen` with truthful first-use/zero-data state until LOS-0615 supplies endpoint data. Creation invitations reuse the shell-owned Quick Add action. The controlled Brain Dump field preserves text and reports that capture is not connected instead of claiming persistence.
