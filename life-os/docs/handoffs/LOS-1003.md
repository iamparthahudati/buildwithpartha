- Replaced the protected `/life-os/app/sprints` and `/life-os/app/sprints/:sprintId` placeholders with the authenticated Sprints experience. Active, Upcoming, and Completed views are keyboard-accessible tabs backed by the `view` URL parameter; selected list context uses `selected`, and a canonical Sprint ID route reloads directly.
- Added a typed Sprint REST/query boundary for list/detail, create/edit, Task commitment add/update/remove, start, and complete. Every write uses the shared cookie/CSRF client, sends the current optimistic Sprint version, and invalidates the Sprint query family only after confirmed success.
- Composed Sprint planning from the existing Sprint form and cards. Users can plan a Sprint, edit its name/goal/date range/capacity, inspect loading/empty/error states, and start a planned Sprint behind an exact confirmation that explains the one-active-Sprint rule and post-start scope history.

Planned and active Sprints support Task selection, story-point estimates, optional scope reasons, point edits, and confirmed removal. The API receives canonical Task IDs while the UI keeps the distinct commitment ID for stable rendering.

Planned/active totals and completed points are derived from those current statuses; completed Sprints retain the API's immutable completion counts and point snapshot even if a Task changes later.

Completion records wins, improvements, action items, summary notes, and either returns open Tasks to the backlog or requires an explicit planned target Sprint whose current ID/version is sent to the transactional API. Completed retrospectives render as read-only history rather than implying they can be edited after the terminal transition.
- Preserved loading, retryable error, empty, pending, conflict/error, confirmation, disabled unavailable-Task, and zero-point/capacity states. Scope timestamps are formatted at the display boundary in the Account locale and IANA timezone.
- Corrected the Sprint component styles inherited from LOS-1002 to use the frozen `--lifeos-*` semantic token contract. Card, Task, and history layouts wrap at narrow widths; coarse-pointer status targets reach 44px; headings no longer skip levels in the composed screen and dialog hierarchy.

## Known limitations or follow-ups

- The scope picker resolves the first 100 current non-archived Tasks, matching the Task API's bounded page size. A commitment outside that page is shown honestly as unavailable and excluded from live completion points; completed Sprint snapshots remain intact. A future large-library picker should use server-side Task search/pagination rather than increasing the bounded response.
- Sprint cancellation and planned-Sprint deletion exist in the backend lifecycle but were not requested by LOS-1003's acceptance contract and are not exposed here. A later planning lifecycle ticket should add them with the documented recoverability policy and exact confirmation copy.
- Conflict responses remain server-authoritative and visible without applying a client-side guess. The user can retry the list/detail query to load the newest version; a dedicated inline merge/reload affordance can be added if Sprint editing proves conflict-heavy.
