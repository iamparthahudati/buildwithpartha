## Completed behavior

- Added domain-neutral `common.activity` and `common.audit` contracts so product domains can emit events without depending on audit persistence internals.
- Product Activity commands accept only Account/actor UUIDs, a closed event enum, canonical Project/Task subject type, and subject UUID. Personal Activity rejects a different actor and owner.
- Product Activity recording captures a safe request correlation ID and UTC occurrence instant transactionally. Subject reads/counts require the Account UUID, remain user-scoped, use stable newest-first ordering, and enforce a maximum page size of 100.
- Security Audit is write-only outside the audit domain. Its typed command permits only closed event/outcome/target enums and optional UUIDs; no free-form string, byte, collection, or map metadata channel exists.
- Security Audit captures an allowlisted correlation ID, persists an explicit 365-day R6 expiry, and runs an idempotent daily cleanup. No user-facing Security Audit controller or read port was added.
- Unsafe/missing MDC correlation values are replaced with generated UUIDs rather than persisted.
