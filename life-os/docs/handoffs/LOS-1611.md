  - Defined end-to-end log management architecture for all 9 production and monitoring services (Caddy, API, web, Postgres, Prometheus, Alertmanager, Blackbox Exporter, Node Exporter, postgres-exporter).

  - Specified three-layer disk-pressure protection: Docker `max-size`/`max-file` caps → logrotate `maxsize` → Prometheus `HostDiskPressure`/`HostDiskCritical` alerts (LOS-1610).
  - Documented correlation search runbook with `search-logs-by-correlation.sh` usage examples.
  - Documented staging parity (7-day retention vs 14-day production).
  - 10 known limitations and follow-ups documented (no Loki in v1, Caddy query-string filter advisory, Docker data-root isolation advisory).

- **Created Docker Logging Driver Config (`infra/compose/compose.prod.yml` — 4 services)**:
  - Added `logging.driver: "json-file"` with `max-size: "100m"`, `max-file: "14"`, `compress: "true"`, `labels: "service"` to: `caddy`, `web`, `api`, `postgres`.
  - Enforces ~1.4 GB uncompressed / ~200–400 MB compressed maximum per service at the Docker daemon level.

- **Created Docker Logging Driver Config (`infra/compose/compose.monitoring.yml` — 5 services)**:

- **Created Logrotate Configuration — Production (`infra/logrotate/lifeos-logs.conf`)**:
  - Covers `/var/log/life-os/*.log` (backup status logs and host-level file logs).
  - `daily`, `rotate 14` (14-day retention), `compress`, `delaycompress`, `missingok`, `notifempty`, `sharedscripts`.
  - `maxsize 500M` disk-pressure guard (forces rotation before daily schedule if file reaches 500 MB).
  - `create 0640 root deploy` — protected permissions on new log files.
  - Deploy to `/etc/logrotate.d/lifeos` on production VPS.

- **Created Logrotate Configuration — Staging (`infra/logrotate/lifeos-logs.staging.conf`)**:
  - `rotate 7` (7-day retention), `maxsize 200M` — suitable for ephemeral staging environment.
  - Deploy to `/etc/logrotate.d/lifeos` on staging VPS.

- **Created Logrotate README (`infra/logrotate/README.md`)**:
  - Step-by-step deployment instructions for production and staging VPS.
  - Dry-run verification command documented (`logrotate -d`).
  - Docker log size inspection commands for operational use.

- **Created Correlation Search Script (`scripts/search-logs-by-correlation.sh`)**:
  - Supports: `--id <value>`, `--field correlationId|traceId|message|any`, `--service api|caddy|web|postgres|all`, `--since <duration>`, `--until <timestamp>`, `--raw`, `--no-colour`.
  - Uses `docker logs --since <duration>` + `jq -c` filter for structured JSON logs (API); falls back to `grep -F` for non-JSON logs (Caddy, Postgres, nginx).
  - Colour-formatted output: timestamp, level, correlationId, traceId, logger class, message.
  - Exits 1 with clear message if no matches found; exits 0 with total match count when matches exist.
  - Validates `docker` and `jq` availability with clear error messages.
  - Marked executable (`chmod +x`).

## Database/config/deployment changes

- **No database schema changes** — log management is infrastructure-only.
- **New Docker logging config** in `compose.prod.yml` and `compose.monitoring.yml` takes effect on next `docker compose up --force-recreate` (or container restart). Existing containers continue with their current logging configuration until recreated.
- **VPS deployment steps required** (per `infra/logrotate/README.md`):
  ```bash
  # Production VPS
  sudo cp life-os/infra/logrotate/lifeos-logs.conf /etc/logrotate.d/lifeos
  sudo chmod 644 /etc/logrotate.d/lifeos
  sudo mkdir -p /var/log/life-os
  sudo chown root:deploy /var/log/life-os
  sudo chmod 750 /var/log/life-os
  sudo logrotate -d /etc/logrotate.d/lifeos  # verify
  ```
- **No new secrets** — logrotate config contains no credentials.
- **jq** must be installed on VPS to use `search-logs-by-correlation.sh`: `sudo apt-get install -y jq`.

## Known limitations or follow-ups

- **No centralized log aggregation service** (Loki/Elasticsearch) in v1 — `docker logs` + jq correlation search is sufficient for a single VPS. A Loki + Grafana integration is a post-launch enhancement.
- **Postgres log verbosity** — `log_min_duration_statement` and `log_line_prefix` are not configured by this ticket. Default PostgreSQL logging settings apply; a follow-up ticket can tune verbosity and confirm parameter values are not logged with slow queries.
- **Docker data-root** is not moved to a dedicated disk partition — log volume is bounded by Docker driver caps and disk alerts; a dedicated partition is a post-launch improvement if disk usage patterns require it.
- **Caddy query-string log filtering** — the Caddyfile `query` log filter (to strip `token=` params from logged URIs) should be applied when the Caddyfile is next modified; documented in spec §6.
