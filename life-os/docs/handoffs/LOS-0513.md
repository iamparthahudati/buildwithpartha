## Completed behavior

Implemented onboarding persistence and user profile / preference management for LifeOS backend and frontend client per `docs/backlog/EPIC-05-IDENTITY.md` and `docs/25-ONBOARDING-SPECIFICATION.md`:

- **Database Migration (`V4__user_preferences_and_onboarding_schema.sql`)**:
  - Created `public.user_preferences` table with `user_id` foreign key referencing `public.users(id) ON DELETE CASCADE`.
  - Stored `onboarding_version` (default 1), `onboarding_status` (`NOT_STARTED`, `IN_PROGRESS`, `COMPLETED`), `last_completed_step` (`WELCOME`, `TIME_AND_WEEK`, `PLANNING_DEFAULTS`, `START`), `onboarding_completed_at`.
  - Stored planning defaults: `working_days` (`INT[]` / `INTEGER ARRAY`), `work_start_time` (`TIME`), `work_end_time` (`TIME`), `overnight_schedule` (`BOOLEAN`), `daily_focus_target_minutes` (`INT`), `focus_duration_minutes` (`INT`), `break_duration_minutes` (`INT`), and optimistic locking `version` (`BIGINT`).
- **Domain Layer (`tech.buildwithpartha.lifeos.user.domain`)**:
  - `OnboardingStatus`, `OnboardingStep` enums.
  - `UserProfile` immutable domain record with `withUpdates`.
  - `PlanningDefaults` record with validation for working days (1..7 deduplicated and sorted), focus/break durations, and sensible defaults (Mon-Fri, 25m focus, 5m break).
  - `UserPreferences` aggregate root managing step advancement, skipping, completion timestamps, and planning defaults.
  - `TimezoneValidator` validating IANA timezone identifiers using `ZoneId.getAvailableZoneIds()`.
  - `UserProfileRepository` and `UserPreferencesRepository` domain interfaces.
- **Application Layer (`tech.buildwithpartha.lifeos.user.application`)**:
  - `OnboardingService`: manages multi-step onboarding lifecycle (`getOnboarding`, `updateWelcomeStep`, `updateTimeAndWeekStep`, `updatePlanningDefaultsStep`, `completeOnboarding`).
  - `UserProfileService`: manages account profile and preference updates (`getProfile`, `updateProfile`, `getPreferences`, `updatePreferences`).
- **Infrastructure Layer (`tech.buildwithpartha.lifeos.user.infrastructure`)**:
  - `UserProfileEntity` & `UserPreferencesEntity` with Spring Data JPA repository adapters (`JpaUserProfileRepository`, `JpaUserPreferencesRepository`).
- **API Layer (`tech.buildwithpartha.lifeos.user.api`)**:
  - `OnboardingController` (`GET /onboarding`, `PUT /onboarding/welcome`, `PUT /onboarding/time-and-week`, `PUT /onboarding/planning-defaults`, `POST /onboarding/complete`).
  - `ProfileController` (`GET /user/profile`, `PUT /user/profile`, `GET /user/preferences`, `PUT /user/preferences`).
- **Security & CSRF Validation**:
  - Updated `SessionAuthenticationFilter` to validate `X-CSRF-TOKEN` for authenticated mutating requests (`POST`, `PUT`, `PATCH`, `DELETE`).
- **Frontend Client (`apps/web/src/features/onboarding` & `apps/web/src/features/user`)**:
  - `apps/web/src/features/onboarding/api/onboardingApi.ts` (+ tests): typed client methods `getOnboarding`, `updateWelcomeStep`, `updateTimeAndWeekStep`, `updatePlanningDefaultsStep`, `completeOnboarding`.
  - `apps/web/src/features/user/api/userProfileApi.ts` (+ tests): typed client methods `getProfile`, `updateProfile`, `getPreferences`, `updatePreferences`.
  - Exported through `features/onboarding/index.ts` and `features/user/index.ts`.
