## Completed behavior

Adds `ErrorState` to `apps/web/src/components/feedback/`, completing the "empty/error" pair `STRUCTURE.md` names for that category alongside `EmptyState` (LOS-0410).

### The tone guide's message formula is the prop shape, not a suggestion

"What happened. What was preserved/current. Next action." maps directly onto `title` (what happened), `description` (what was preserved), and `onRetry`/`onGoBack`/`onSignIn`/`action` (next action) — the same "copy is always the caller's, the component only supplies structure" rule `EmptyState` already established, extended here with three **named** recovery actions because, unlike `EmptyState`'s always-domain-specific primary action ("Add project", "Clear filters"), the tone guide standardizes these three tightly: `Try again` appears verbatim in every retry example, `Sign in again to continue` is the fixed auth-expiry copy. Dedicated `onRetry`/`onGoBack`/`onSignIn` props (each with an overridable but canonically-defaulted label) exist specifically to stop an inconsistent label from creeping in call site by call site — a value a fully generic action slot could not provide on its own.

An `action` escape hatch still exists beside the three named ones, for a recovery action none of them cover — the tone guide's Conflict example (`Compare changes` / `Copy my changes` / `Load latest`) needs exactly this, and the catalog's own escape-hatch specimen composes it alongside a renamed `onRetry` (`Load latest`) to prove the two are not mutually exclusive.

### `scope="region"` is an `Alert`; `scope="page"` cannot reuse `EmptyState`

The tone guide's "Partial failure" rule keeps the rest of the page visible around a region-scoped error, which is exactly what an inline `Alert` (LOS-0408, the ticket's stated dependency) already does — `scope="region"` composes it directly rather than drawing a second box shape. `scope="page"` needed its own markup rather than reusing `EmptyState`: `EmptyState`'s `variant` type names *reasons a list is empty* (first-use, filtered, search, permission, archived), not *reasons a load failed*, and routing an error through that type would be a false claim about what those five values mean. The two components share only the underlying visual language (`Surface` + `Icon` + `Heading` + `Text` + actions), not a shared type.

### Region's own heading is a paragraph, not a document heading

Composing `Alert` means the region variant's `title` renders through `Alert`'s own `heading` prop — a bold lead-in `<p>`, not a semantic `<h*>` — which is correct for a region error the same way it is for `Alert` itself: a widget-level failure is not a landmark in the page's document outline, only the page around it is. This surfaced as a real assertion the first test draft got wrong (`getByRole("heading")` found nothing), fixed by checking the visible text instead of assuming a heading role that was never claimed.

## Known limitations or follow-ups

- No offline-banner or conflict-dialog primitive — those are the tone guide's "Offline" and "Conflict" sections, and while `ErrorState`'s escape hatch can express a Conflict's three actions (proven in the catalog), a persistent offline banner is a distinct always-on pattern outside a single error state and is not this ticket's scope.
- `onRetry`/`onSignIn` both render as primary `Button`s; nothing stops a caller from supplying both at once, which would show two visually-equal primary actions side by side. Real usage should not need both together (retry doesn't help an expired session, and vice versa), so no additional guard was added for a combination the tone guide's own examples never call for.
