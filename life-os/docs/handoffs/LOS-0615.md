## Completed behavior

Integrated the complete Today screen with the authenticated foundation aggregation (`GET /today`) while retaining the independent component state contracts completed in LOS-0608–LOS-0614.

- Added a typed Today API client covering the 13 modular widgets. It calls the shared `apiRequest` client, so requests remain same-origin and cookie-authenticated and an `AUTHENTICATION_REQUIRED` response uses the existing global session/query-cache clearing and safe sign-in return path.
- Added a TanStack Query hook keyed by the confirmed account timezone. It keeps last confirmed data during background refresh, refetches on window focus, exposes a shared `TODAY_QUERY_KEY` invalidation boundary for later domain mutations, and invalidates Today within 30 seconds of the user's local-date boundary.
- Added a presentation mapper that maps MIT, Tasks, schedule/current-next state, Focus, Sprint, extended Weekly Plan data, active Projects, Daily Review, Brain Dump count, and six metrics into the existing `TodayScreen` props without changing the composed screen. Current foundation `EMPTY` widgets remain truthful first-use states.
- Provider `ERROR` states remain inside their owning regions with retry controls that refetch the aggregate. Successful siblings remain visible, and safe client copy never exposes backend provider error text.
- Ready Task and Time Block projections receive canonical encoded routes, timezone-safe due labels, deterministic current/next/conflict state, and canonical priority/status mapping. Next up appears only when no active MIT hides it and ranks open Tasks by the documented priority, due-date, then provider-order rule with a recorded-fact explanation.
- Metric values prefer an explicit matching Metrics-provider value and otherwise derive from the corresponding canonical widget. Missing denominators remain empty messages instead of invented `0%` values.
- The route uses the response timezone/local date and `generatedAt`. When cached data is available offline, the screen names its last confirmed update; without cached data, it says no confirmed Today data is available. Server-dependent actions remain unavailable.
- First-use Add Task, Add Time Block, Add Project, and Quick Add actions continue to use the shell-owned Quick Add dialog; Choose/Change MIT opens canonical Tasks. Task/MIT/Focus mutations that do not yet have owning APIs are visibly disabled rather than wired to no-op behavior.
- Brain Dump text remains controlled and preserved after an online failure. Because this integration has no approved account/session-scoped offline draft store, offline capture is disabled with exact reconnect guidance instead of claiming persistence.

- The foundation backend providers intentionally return typed `EMPTY` states until their owning domain epics ship. This integration already maps populated contract fixtures without a `TodayScreen` rewrite.
- The current Week payload exposes task counts/outcomes but not the full date/day/capacity fields needed by the ready Weekly Plan component. It contributes the defensible Week metric now and keeps the full panel empty until the later provider supplies those modular fields.
- Canonical MIT/Task completion, Time Block/Focus start, and Brain Dump create mutations belong to their owning later domain tickets. Their unavailable Today controls are disabled or preserve input honestly; `invalidateTodayQueries` is ready for those mutation success handlers.
- Overdue and Habits are present in the aggregation but do not yet have completed composed Today components. LOS-1415 owns the full real-data Today aggregation closure.
