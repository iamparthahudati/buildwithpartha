## Completed behavior

Implemented the authenticated Habits API on the LOS-1208 domain and persistence model.

- Habit create/list/read/update endpoints expose cadence, positive target count, IANA timezone, appearance, reminder preference, archive state, timestamps, and optimistic version. Lists can include all Habits or filter active/archived records.
- Archive and restore require the current non-negative version, reject stale writes with `409 CONCURRENCY_CONFLICT`, and return the current record without another write when the requested lifecycle state is already applied.
- Permanent delete verifies ownership and removes entries and pause periods before the Habit; PostgreSQL's cascade remains a second database-level safeguard.
- Entry APIs list an inclusive range, return the Habit's timezone-derived current local date, increment the single entry for a local date, set an absolute positive count, and idempotently remove a date entry. Range reads are capped at 366 local dates.
- Pause APIs create inclusive bounded or open-ended ranges, list them, validate date ordering, and remove only a pause belonging to the owned Habit.
- Statistics return calendar days, days with an entry, days meeting the Habit target, total completions, and the target-meeting rate for an inclusive range of at most 366 dates.
- All endpoints use stable explicit OpenAPI operation IDs, safe shared Problem responses, session authentication, CSRF protection on writes, request DTO validation, and owner-scoped `404 RESOURCE_NOT_FOUND` behavior that does not reveal another Account's records.

## Known limitations or follow-ups

- The statistics endpoint is intentionally a plain date-window projection. It does not claim streak or cadence eligibility and does not remove paused dates from its denominator; LOS-1210 owns cadence, pause, late-edit, missed-day, timezone-change, count-target, rounding, and deterministic streak rules.
- Increment is additive by design: repeated intentional calls add to the one canonical daily row. Retry-safe absolute updates are available through `PUT /entries`; removal and lifecycle no-ops are idempotent. A future offline mutation queue that replays increment commands should add an operation idempotency key before enabling that path.
- The repository-wide backend gate remains red because of the unrelated Brain Dump/Today regressions above. LOS-1209 neither changes those files nor masks the failures.
