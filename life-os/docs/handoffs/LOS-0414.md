## Completed behavior

Adds `Drawer` and `DetailPanel` to `apps/web/src/components/feedback/`, plus a new standalone hook, `hooks/useDeepLinkParam.ts`.

### Drawer shares Dialog's mechanics rather than reimplementing them

`Drawer` reuses `useFocusTrap` and `dialogStack.ts` directly — the same two pieces LOS-0412 extracted specifically because "a Drawer, a Menu or a Command Palette... needs the identical guarantee." A Drawer is a `Dialog` with edge-anchored positioning and slide motion, not a different set of accessibility guarantees: focus trap, focus restore, Escape, backdrop dismissal and the body scroll lock all work exactly as they do for `Dialog`, and a `Drawer` opened over a `Dialog` (or another `Drawer`) closes only the topmost layer — proven with the same nested-Escape test shape LOS-0412 used, now crossing between the two components rather than staying within one.

"Side/full-screen responsive variants" is read literally: responsive means automatic by breakpoint, not a size prop a caller picks. `placement` chooses which edge a Drawer slides from on a wide viewport; below 768px every placement becomes the same full-screen sheet, matching the mobile treatment `Dialog`'s own CSS already uses.

### The dirty-state guard intercepts dismissal, not detection

`isDirty` is a plain controlled boolean — detecting dirtiness stays the caller's job, the same "component supplies the mechanism, caller supplies the state" split every controlled composed component here already uses. What `Drawer` supplies: while `isDirty` is true, Escape, the backdrop click and the close button all open an internal `ConfirmDialog` ("Discard unsaved changes?") instead of calling `onClose` directly, and only a confirmed discard calls the real `onClose`. Cancelling the confirmation returns the user to the still-open, still-dirty Drawer with nothing lost — tested explicitly, not just the "it eventually closes" happy path.

### `useDeepLinkParam` — a real URL sync without a router

No routing library is wired into LifeOS yet; `routes/index.ts` is still LOS-0201's reserved placeholder. Rather than inventing a throwaway navigation model that would need rewriting once real routing lands, `useDeepLinkParam` is built directly on `history.pushState` and the `popstate` event — the primitive any router eventually sits on top of. This gives `DetailPanel` a genuinely working deep link today: `open(id)` changes the URL for real, a copied/reloaded link reopens the same value, and `close()` calls `history.back()` rather than pushing a new "removed" state, which is what makes the browser's own Back button behave identically to clicking the panel's close control — the ticket's "stable close/back behavior."

`DetailPanel` does not own this hook internally. It takes plain `open`/`onClose`/`content` props like `Drawer` does; the caller calls `useDeepLinkParam` themselves, uses its `open` to wire up their own trigger (a list row's click, say), and resolves whatever the current value points to into `content`. Owning the hook inside `DetailPanel` would have left the caller with no way to open the panel from outside it in the first place.

### DetailPanel's real value-add: the loading/not-found shape every "show one record" panel needs

`content: ReactNode | null | undefined` — `undefined` while resolving, `null` once known not to resolve, otherwise the real content. `DetailPanel` composes `Spinner` for the first case and `EmptyState`'s `permission` variant for the second, reusing `29-PRODUCT-VOCABULARY.md`'s own "Not found/private" copy pattern (`This item isn't available… may have been removed, or you may not have access.`) rather than inventing a third "not found" shape — a shared link to a record since deleted is exactly the ambiguity that copy is written to cover honestly.

## Known limitations or follow-ups

- `useDeepLinkParam` manages exactly one query parameter; a screen needing several deep-linkable values (a record id and a tab within it, say) composes multiple instances rather than this hook growing a multi-parameter API it does not need yet.
- No true router integration — by design, until Epic 06 lands one. `useDeepLinkParam`'s `open`/`close` contract (a value in, `history.pushState`/`back()` under the hood) is deliberately narrow enough that swapping its internals for a real router's navigation API later should not require changing anything that calls it.
- `DetailPanel`'s not-found copy is fixed to the tone guide's generic "Not found/private" wording via overridable props; a screen needing per-entity phrasing (`This Task isn't available` versus `This Project isn't available`) already can via `notFoundTitle`/`notFoundDescription`, just not automatically from the id alone.
- Nested Drawer/Dialog stacking shares one `--lifeos-z-dialog`/`--lifeos-z-drawer` token pair per type rather than a per-instance depth-derived value, the same simplification recorded as a known limitation in LOS-0412 — still fine only because each layer's own backdrop fully covers the one beneath it.
