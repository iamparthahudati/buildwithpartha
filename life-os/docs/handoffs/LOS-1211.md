## Completed behavior

Built the complete frontend component layer for LifeOS Habits, ready for LOS-1212 screen composition and API integration.

- Added API-aligned TypeScript models for Habit, Habit Entry, pause periods, streak statistics, heatmap dates, and create/edit values. Presentation helpers format cadence, count targets, reminder times, bounded completion rates, and deterministic heatmap levels without changing canonical values.
- `HabitCard` presents the Habit name, description, cadence, target, IANA timezone, reminder state/time, active/paused/archived lifecycle, optional streak statistics, current local-date entry controls, and exact edit/pause/resume/archive/restore actions. It includes loading, empty, region-error, paused, archived, disabled, and pending states.
- `HabitRow` provides the same canonical identity, lifecycle, target progress, entry and action contract in a compact responsive layout with exact accessible names on icon actions.
- `HabitEntryControl` exposes an honest target-aware count, determinate progress, increment/decrement callbacks keyed by Habit and local date, and explicit pending, target-met, paused, archived, loading, disabled, and recoverable-error behavior.
- `HabitStreakSummary` presents current streak, longest streak, completion rate and eligible-period count. Its copy explicitly says paused periods are excluded and does not shame missed periods. Loading, no-history and recoverable-error states preserve the metric layout.
- `HabitHeatmap` maps completion/target ratios into token-based intensity levels, gives the visual a factual prose summary, represents pauses separately, and uses `ChartFrame` to replace the graphic with a real date/completions/target/result table. The table scrolls inside its own region at 320px without widening the page.
- `HabitFormDialog` validates name, description length, positive whole-number target, timezone, and reminder-time requirements; preserves optimistic versions; supports create/edit, dirty, pending, server-error and changed-elsewhere recovery states; and explains that timezone changes do not re-bucket existing local dates.
- `HabitReminderFields` keeps reminders off by default and explicitly avoids implying that the setting itself enables email or browser notifications.
- `HabitPauseDialog` supports bounded and open-ended inclusive local-date pauses with optional reason and ordered-date validation. `HabitArchiveDialog` names the recoverable consequence and restoration path before archive.
- Added eight interactive catalog specimens covering ready, interactive, pause/archive, loading, error, disabled and archived states.

## Known limitations or follow-ups

- LOS-1211 intentionally supplies controlled components only. LOS-1212 owns Habit API functions, TanStack Query hooks, Today/list/detail/history/statistics screen composition, optimistic mutation rollback, URL date state and routed integration.
- The backend currently exposes plain day-window statistics but not `HabitStreakCalculator` results. LOS-1212 must add or consume an authoritative pause-aware streak projection before showing server-derived streak values; it must not calculate a divergent rule in the browser.
- Reminder delivery remains subject to the existing notification/privacy gates. The component records only the Habit reminder preference and never requests browser permission or claims email delivery.
- The unrelated Projects route page-size test mismatch remains on `develop` and should be reconciled in the owning Projects follow-up.
