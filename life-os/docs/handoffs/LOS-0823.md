## Completed behavior

- Added authenticated `GET /tasks/{taskId}/activity` and `GET /projects/{projectId}/activity` endpoints with stable newest-first zero-based pagination, defaults of page 0/size 20, and a maximum size of 100.
- Returns structured `id`, `actorUserId`, closed `eventType`, optional current object, and UTC `occurredAt`. Available objects expose only canonical type/UUID, a current owner-scoped label, and an internal LifeOS link.
- Returns `object: null` when a Task/Project was deleted or current owner-scoped resolution is unavailable. Soft-deleted Tasks and hard-deleted Projects remain history-readable only when that Account owns Activity for the exact typed subject; missing and cross-user subjects remain the same `404 RESOURCE_NOT_FOUND`.
- Emits typed transactional events for Project create/update/archive/restore/delete; Task create/update/status/archive/restore/delete/duplicate/bulk/MIT/dependency changes; Subtask create/update/complete/delete/reorder; and automatic dependent unblocking. Existing Comment create/update/delete events remain part of the same feed contract.
- Fans linked Task changes into the current Project feed, and into both affected Project feeds when a Task moves. Idempotent lifecycle and bulk no-ops do not create duplicate events.
- Stores only typed feed/object UUID references. Current Task/Project labels are resolved on read; no title, description, Comment/Subtask body, request body, correlation ID response field, arbitrary metadata, or whole-record before/after snapshot is stored or exposed.

## Known limitations or follow-ups

- LOS-0823 intentionally adds no frontend integration. LOS-0824 owns event-type-to-copy/icon mapping, current Account actor naming, filtering, pagination controls, accessible timestamps, and mutation-driven refresh.
- Activity rows remain content-free and therefore cannot reconstruct historical titles or field-level before/after values. This is intentional: a deleted/unavailable object uses the safe fallback, and a renamed object uses its current label.
- The Activity API does not expose the internal correlation ID or Security Audit Events.
