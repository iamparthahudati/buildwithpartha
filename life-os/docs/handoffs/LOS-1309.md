## Completed behavior

- **Authored & Accepted ADR-015 (`docs/adr/ADR-015-ATTACHMENT-STORAGE-AND-QUOTAS.md`)**:
  - Established binding architecture decision for file attachment storage, quotas, scanning, access control, backup, and privacy.
  - Specified private S3-compatible object storage interface (`attachments/{accountId}/{attachmentId}`) supporting MinIO for local dev/test parity and AWS S3 / Cloudflare R2 for production.
  - Defined explicit quota bounds: 25 MB max per file, 2 GB total per account, and max 20 attachments per entity (Task / Project).
  - Defined strict MIME type allowlists (JPEG, PNG, GIF, WebP, PDF, TXT, MD, DOC/X, XLS/X) with mandatory backend magic-byte binary header inspection. Forbidden: Executables, HTML, SVG, and unknown binary streams.
  - Specified authenticated backend stream download proxying (`GET /api/v1/attachments/{id}/download`) with `Content-Disposition: attachment` and `X-Content-Type-Options: nosniff` headers to block unauthenticated direct storage access and prevent stored XSS.
  - Defined asynchronous malware scanning lifecycle (`PENDING_SCAN` -> `CLEAN` / `QUARANTINED`) via `BackgroundJob` framework (LOS-1403) with ClamAV integration.
  - Integrated attachment retention with 30-day Account deletion grace period (LOS-0518) and ADR-012 35-day backup lifetime limits.
  - Enforced feature toggle control `lifeos.features.attachments.enabled` (defaults to `false`), keeping UI attachment controls hidden until implementation (LOS-1310) and integration (LOS-1311) complete.
