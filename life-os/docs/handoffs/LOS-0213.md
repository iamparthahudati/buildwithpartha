## Completed behavior

Added one versioned `application/problem+json` response for expected, validation, malformed, missing-resource, authentication, authorization and unexpected failures. Each response carries a stable code and correlation ID while excluding exception diagnostics, rejected values and query data.

Every response now receives `X-Correlation-ID`. Safe caller IDs are propagated; missing or unsafe IDs are replaced with UUIDs and the selected value is available to the logging context.

Only aggregate `GET /actuator/health/liveness` and `GET /actuator/health/readiness` probes are public. Readiness includes database state internally, while component/detail output, actuator discovery, the health root and other actuator capabilities remain unavailable or denied.

## Files and contracts changed

- Added immutable Problem Details/field-error contracts and standard cross-cutting error codes under `common.error`.
- Added the correlation filter, problem factory/advice and deny-by-default servlet security policy under `config`.
- Restricted Spring Boot actuator exposure/access and enabled explicit liveness/readiness groups.
- Disabled the generated development user because identity remains owned by the later authentication epic.
- Documented the exact error, correlation, health, security and test contracts.
