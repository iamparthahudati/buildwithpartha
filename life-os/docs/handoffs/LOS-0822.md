## Completed behavior

- Added one shared frontend Comments feature for the LOS-0821 nested Task/Project API: bounded newest-first pages, plain-text create/edit, versioned edit, and `If-Match` versioned permanent delete through the existing cookie/CSRF-aware API client.
- Wired the existing shared `CommentComposer` and `CommentList` into direct and list-sheet Task Details plus Project Details. Both surfaces use the signed-in Account name, server-owned authorization flags, safe UI-authored failure copy, retryable list errors, and 20-item pagination.
- New comments appear immediately as an announced `Posting…` local row and remain visibly unconfirmed until the server response and refreshed page arrive. A failed add removes the local echo but preserves the composer draft and displays a retryable error.
- Edit and delete use the current Comment version. Edit preserves the changed body after failure, concurrency failures explain that the Comment changed elsewhere, delete remains confirmed and pending until the API permanently removes it, and archived Task/Project lifecycle rules continue to suppress create/edit controls while retaining allowed reads/deletes.
- Comment bodies remain text-only in React. Raw HTML, event-handler text, and Markdown-shaped unsafe links are never parsed or inserted as markup. Inline edit now moves focus directly from the removed Edit control to the textarea; the delete dialog continues to focus Cancel by default.
