## LOS-0308 — Link

`Link` navigates. Anything that changes state without going somewhere is a `Button` with the `link` variant — that split is the whole reason both exist.

There is deliberately **no `disabled` prop**. A disabled anchor is not a real thing: dropping `href` strips the link role and removes the element from the tab order without telling anyone why it is unreachable. When a destination is genuinely unavailable, render text; if it was an action all along, render a disabled button.

`current` renders `aria-current="page"`, so the current destination is announced rather than only styled. `external` opens in a new tab, appends a decorative indicator **and** a spoken "(opens in a new tab)" note, and always sets `rel="noreferrer noopener"` — `noopener` denies the opened page access to `window.opener`, `noreferrer` withholds the referrer. `quiet` drops only the resting underline for dense navigation lists; hover restores it and the shared focus ring is untouched, so neither pointer nor keyboard users lose the affordance.

## LOS-0309 — Badge and StatusDot

Every badge renders text. Colour accompanies meaning and never carries it, because a red dot alone conveys nothing to someone who cannot distinguish it or who is using a screen reader.

Canonical `TASK_STATUS_TONE` and `PRIORITY_TONE` maps come from [the product vocabulary](../29-PRODUCT-VOCABULARY.md), so a status cannot pick up an ad-hoc colour at a call site. `P1` is the only priority that reads as urgent.

`StatusDot` requires a `label` and is exposed as a named image, since a bare dot says nothing. `DecorativeStatusDot` is the counterpart for a dot sitting beside text that already states the status — hidden from assistive technology so the status is not announced twice. Making these two separate components, rather than one component with a flag, means the call site has to decide which situation it is in.

`CountBadge` clamps its visible number ("99+") so a badge cannot stretch a layout, while still announcing the exact count and naming what is being counted.

## LOS-0310 — Avatar

Image, initials, broken-image fallback, and a group with overflow.

The accent colour is **hashed from the name**, not random and not stored, so the same person keeps the same colour across sessions and devices — which is what makes it recognisable rather than merely colourful. Each of the six accents pairs a soft background with its own AA-passing text colour, so initials stay legible whichever one a name resolves to.

Initials are taken by **code point**, so a name beginning with an emoji or an astral character is not split into half a surrogate pair and rendered as a box.

An avatar is decoration next to a visible name in almost every layout, so it is hidden from assistive technology by default; `standalone` exposes it as a named image for the rare case where no name accompanies it. A failed image URL falls back to initials rather than leaving a blank hole where a person should be. `AvatarGroup` carries one accessible name for the whole group, because announcing each face turns a glanceable summary into a long list.

## Known limitations or follow-ups

- `Link` renders a plain anchor. When routing lands it will need a router-aware variant so internal navigation does not force a full page load; the `current` and `external` contracts should survive that change unchanged.
- Avatar accent assignment is uniform across six buckets, so two people in the same small group can share a colour. Colour is never the only identifier — initials and the accessible name always accompany it — so this is cosmetic.
- `AvatarGroup` names every person including those collapsed into the overflow chip. For a very large group that accessible name gets long; a cap on the spoken list may be worth revisiting when a real screen uses it.
- Badge tones were verified against the frozen token pairings, but rendered contrast still needs browser verification at LOS-0332.
