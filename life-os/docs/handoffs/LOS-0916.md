## Completed behavior

- Extended the existing Account-owned user-preferences aggregate with a 15-minute long break, four Focus Sessions per cycle, automatic break/focus start choices, local sound choice, and browser-notification choice while preserving the established 25-minute focus and 5-minute break defaults.
- Defaults are conservative: automatic starts, sound, and browser notifications are all off. Focus and existing short-break durations retain their 1–1,440-minute API compatibility bound; long breaks are bounded to 1–180 minutes; and cycle length to 1–12 Focus Sessions in the domain, API validation, database constraints, and UI.
- Extended authenticated `GET`/CSRF-protected `PUT /user/preferences` responses and writes. Older clients may omit the new fields during a rolling deployment; the server retains their current stored values instead of resetting them.
- Added a dedicated, URL-addressable Focus section to Settings with responsive duration/cycle fields, submitted auto-start/sound choices, dirty/pending/success/error states, and complete-payload updates that preserve unrelated working-day, work-hour, and daily-target preferences.
- Browser notification permission is requested only after the user explicitly enables the option. Unsupported, dismissed, and denied permission states remain off with actionable copy; LifeOS persists no browser token or device identifier.
- Updated the shared preferences query cache after save so the existing Focus Mode and mini-player use new focus/break defaults on their next start. An active Focus Session retains its canonical planned values.
- Included every new preference in the existing account data export.

## Known limitations or follow-ups

- LOS-0916 owns persisted choices and settings. The existing LOS-0913/LOS-0915 Focus Session state machine still represents one focus phase followed by one break and does not yet execute a recoverable multi-session long-break cycle or consume auto-start/sound choices; the settings copy describes those choices as preferences for supported transitions rather than claiming an unimplemented device effect.
- Browser phase-end alerts are not emitted yet; LOS-0916 stores the preference and obtains deliberate browser permission without adding a service worker, background notification delivery, or an audio asset.
- Browser notification permission is device-specific and cannot be synchronized by an Account preference. A stored enabled choice still requires `Notification.permission === "granted"` in each browser.
- Session settings inside full Focus Mode remain a deliberate one-start override; they do not silently replace the Account defaults.
