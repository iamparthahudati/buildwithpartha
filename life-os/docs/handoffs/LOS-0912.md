## Completed behavior

- Added the immutable, server-authoritative `FocusSession` aggregate with canonical `RUNNING`, `PAUSED`, `COMPLETED`, and `CANCELLED` states and `FOCUS`/`BREAK` phases.
- Added monotonic state transitions for start, pause, resume, start break, resume focus, complete, and cancel. Running phase time is settled exactly once at each transition; paused time never contributes to actual focus or break duration.
- Modeled positive planned focus duration, non-negative planned break duration, separately accumulated actual focus and break durations, optional Task and Time Block context, server clock anchors, terminal timestamps, ownership, and optimistic version.
- Added private `FocusSessionInterruption` records with optional normalized plain-text notes limited to 2,000 characters and ownership-scoped persistence.
- Added ownership-scoped repository contracts and JPA adapters. No unscoped read-by-ID operation is exposed by the Focus Session domain repository.
- Added PostgreSQL constraints for canonical state/phase values, duration and timestamp validity, valid per-state clock shapes, same-owner Task/Time Block attachment, cascading account/session deletion, and context nullification when a linked Task or Time Block is deleted.
- Enforced at most one active (`RUNNING` or `PAUSED`) Focus Session per user through a PostgreSQL partial unique index, covering concurrent inserts beyond application-level checks.
