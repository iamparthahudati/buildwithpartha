## Completed behavior

- Added authenticated, CSRF-protected Sprint create/list/read/update/delete, start, cancel, scope mutation and complete/carry-over endpoints under `/sprints`.
- Enforces inclusive date validity, non-overlapping non-cancelled windows, one Active Sprint per Account, owner-only Sprint and Task access, available-Task commitment, and explicit optimistic versions on every mutation.
- Serializes date/active/carry-over decisions by locking the Account row, with database one-active and relational/check constraints as independent protection.
- Preserves Task commitments after scope removal and appends immutable Created, Updated, Goal changed, Capacity changed, Started, Task added/removed, Points changed, Completed, Cancelled and Carried over events.
- Completes an Active Sprint with stable committed/completed/added/removed/carry-over counts, total/completed story points, retrospective notes, reflection fields and action items.
- Supports explicit completion to Backlog or transactional carry-over of open, non-duplicate commitments into an owned, versioned Planned Sprint.

## Files and contracts changed

- Flyway V19 and the H2 validation schema add `sprints`, `sprint_action_items`, `sprint_tasks` and `sprint_events`.
- The Sprint module now contains API, application, domain and JPA persistence boundaries.

- Updated the Epic 10 backlog, current status, domain model, API conventions, privacy inventory and this handoff.

## Known limitations or follow-ups

- Sprint task responses intentionally expose canonical commitment IDs, Task IDs and scope metadata; LOS-1003 should resolve current Task titles/status/project context through the existing canonical Task query rather than persisting copied Task content.
- Sprint dates are explicit local dates. A future timezone-aware automation must use the Account timezone at the scheduling boundary without converting stored dates to instants.
- Carry-over targets an already-created Planned Sprint; automatic Sprint creation is outside this API contract.
