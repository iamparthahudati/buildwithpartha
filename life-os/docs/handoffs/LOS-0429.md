## Completed behavior

Adds `BarChart`, `LineChart` and `DonutChart` to `components/navigation/` — hand-rolled SVG, not a charting dependency. `DEPENDENCY-POLICY.md` treats a new direct package as its own deliberate, reviewable ticket ("Application tickets consume the committed dependency state; they do not update … direct packages … as incidental cleanup"), so adding one for this ticket was never an option on the table.

### One coordinate system, shared by all three

Every chart uses a `0–100` viewBox on both axes stretched with `preserveAspectRatio="none"`, which is what makes them "responsive" with no `ResizeObserver`: the SVG simply fills whatever box its container (typically `ChartFrame`, LOS-0428) gives it. The shared `ChartTooltip` (not exported — an internal implementation detail of the three) positions itself by percentage rather than a measured pixel rectangle, because a data point's own viewBox coordinate already *is* the percentage of the rendered container it needs.

Shared, tested pure math lives in `chartScale.ts` (`linearScale`, `valueDomain`, `donutSegments`, `donutSlicePath`, `pointOnCircle`) and `chartValueFormat.ts` (`formatChartValue`, `formatChartPercent`, both `Intl.NumberFormat` `notation: "compact"` — shipped since Firefox 90/Safari 14.1, inside this project's frozen browser target the same way `lib/duration.ts` documents for its own formatting choice).

### Zero/negative/large values — a different answer per chart shape

- **Bar/Line**: `valueDomain` always includes zero as the baseline. A negative value renders as a bar extending below that baseline, or a line point plotted below it — the scale never clips it.
- **Donut**: a pie slice is area, and area cannot be negative. `donutSegments` clamps a negative value to zero — the same "clamped for display" reading `TimerRing` (LOS-0427) already gives an out-of-range `remainingSeconds` — and a series summing to zero renders a plain track-colored ring (`ProgressRing`'s own `is-empty` treatment, LOS-0322) rather than nothing.
- **Large**: `formatChartValue`'s compact notation is used for every label, tooltip and center text by default; a caller can override it with `valueFormatter`.

### Keyboard access, and a real bug two rounds of live-browser testing caught

All three use the same roving `tabIndex` `Menu` (LOS-0415) established: ArrowLeft/Right move it, Home/End jump to the ends. The first pass only updated the `tabIndex` attribute — real DOM focus (and the tooltip that follows it) silently stayed on the old point. A unit test written to check exactly this (`toHaveFocus()` after `ArrowRight`) caught it immediately; the fix is an effect that moves real focus to match, explicitly skipped on the component's own first render so mounting a chart never steals focus on its own.

A second, narrower bug only surfaced in jsdom during that same test: `aria-label` is not a permitted ARIA attribute on a plain SVG `<rect>`/`<circle>`/`<path>` with no role — axe's `aria-prohibited-attr` rule caught it. Every data-point shape now carries `role="img"`, read as "this one shape is a small graphic representing this one value," which is exactly what `aria-label` requires to be valid there.

## Known limitations or follow-ups

- No axis ticks/gridlines beyond a single zero baseline (Bar/Line) — a screen needing labeled Y-axis gridlines would need that added as a real extension, not something implied by "token-based responsive charts" in the ticket's own wording.
- Print behavior is deliberately minimal: `print-color-adjust: exact` so chart fills survive printing, and the floating `ChartTooltip` hides entirely under `@media print` (the same "absent from a printed page" rule `Tooltip`, LOS-0326, already documents for hover-only content). No print-specific layout beyond that.
- `DonutChart` has no interactive legend of its own; a caller composing it inside `ChartFrame` supplies `ChartLegend` (LOS-0428) separately, matching how `BarChart`/`LineChart` also render no legend internally.
