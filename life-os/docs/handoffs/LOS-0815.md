## Completed behavior

- Built `SubtaskChecklist` as a reusable Task Details presentation component over the ordered Subtask projection established by LOS-0804.
- Supports adding, inline editing, completion toggling, ordered movement, and confirmed permanent deletion. Reordering is available through named Move up/Move down buttons and `Alt+ArrowUp` / `Alt+ArrowDown` while a Subtask control has focus.
- Displays exact completed/total progress without inventing a percentage when no denominator exists. When every Subtask is done, the component explicitly states that the parent Task remains open until it is marked done separately; the public contract exposes no parent-completion callback.
- Handles loading, first-use empty, region load error with retry, read-only/permission, validation, pending, isolated partial-operation failure with retry, success announcement, and destructive confirmation states.
- Preserves add/edit drafts when callback promises reject, keeps confirmed Subtasks visible around item-scoped failures, prevents duplicate activation while a request is pending, and returns focus from inline editing and deletion confirmation safely.
- Added development catalog specimens for interactive, pending/partial-error, empty, read-only, load-error, and loading states.
