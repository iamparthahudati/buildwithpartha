## Completed behavior

- Implemented task dependency modeling and REST capabilities:
  - Database schema: Created `public.task_dependencies` table migration (`V11__task_dependencies_schema.sql`) with composite primary key `(blocking_task_id, blocked_task_id)`, check constraint `ck_task_dependencies_no_self`, foreign key cascades `ON DELETE CASCADE`, and indexes `ix_task_dependencies_blocked_task_id` and `ix_task_dependencies_blocking_task_id`. Updated test schema `schema.sql`.
  - Domain Model & Cycle Validation:
    - `TaskDependency` domain record, `TaskDependencyType` enum (`BLOCKER`, `DEPENDENT`), `TaskDependenciesSummary` record.
    - `DependencyCycleValidator`: Graph traversal detecting self and cycle dependencies prior to edge insertion.
  - Task Service & Unblock Automation:
    - Added `addDependency`, `removeDependency`, `getTaskDependencies` in `TaskService`.
    - Integrated automatic dependent task unblocking: when a blocker task transitions to a terminal state (`DONE` or `CANCELLED`), dependent tasks in status `BLOCKED` with no remaining open blockers transition automatically to `TO_DO`.
  - Task Dependency API:
    - `GET /tasks/{taskId}/dependencies` — Retrieves blockers, dependents, `isBlocked` flag, and `unresolvedBlockerCount`.
    - `POST /tasks/{taskId}/dependencies` — Adds a dependency edge with cycle & self-dependency validation.
    - `DELETE /tasks/{taskId}/dependencies/{targetTaskId}` — Removes a dependency edge.
