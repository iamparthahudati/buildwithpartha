## Completed behavior

- Built `DependencyEditor` as a reusable Task Details presentation component over the directional Task dependency projection established by LOS-0807. The owner explicitly confirmed LOS-0807 as Done before implementation began.
- Supports searching and selecting blocker Tasks through the shared ARIA Combobox, with the current Task and existing blockers unavailable for selection. The add flow preserves a failed selection, prevents duplicate activation while pending, supports safe retry, and returns focus to its trigger after dismissal or success.
- Renders independent `Blocked by` and `Blocks` lists with canonical Task status/priority labels, explicit unresolved/resolved blocker state, direct Task links or an `onOpenTask` fallback, and unlink controls for both relationship directions.
- Explains self-dependency, dependency-loop, permission/unavailable, conflict, and unexpected failures with UI-owned safe copy. Item-scoped pending and failure states leave unrelated relationships available.
- Covers loading, first-use empty for each direction, region load error with retry, read-only permission, temporarily disabled/offline-style, pending, partial failure, success announcement, and responsive dialog states.
- The blocker picker becomes a true full-viewport dialog at the smallest viewport, with a sticky action row and safe-area padding. Mobile rows and the Surface header collapse without horizontal overflow; tablet and desktop retain the denser two-column rows.
- Added development catalog specimens for interactive, cycle explanation, pending/partial failure, empty, read-only, load-error, and loading states.

## Known limitations or follow-ups

- This component is intentionally presentation-first. LOS-0818 composes it into Task Details, and LOS-0820 maps LOS-0807 dependency queries/mutations and Task search into its controlled contracts.
- LOS-0807 returns the same safe `INVALID_DEPENDENCY` field code for self-dependency and cycles. `DependencyEditor` prevents choosing the current Task locally, so LOS-0820 can map an `INVALID_DEPENDENCY` response for a distinct selected Task to the approved loop explanation without exposing backend detail.
- Candidate search result ordering, pagination, and network debounce remain caller-owned; the component delegates query changes and passes the current result set to the existing Combobox.
- LOS-0807's handoff is complete and the owner explicitly confirmed it as Done, but the older backlog ledger still leaves it unlisted. Correcting that historical ticket ledger is outside LOS-0816's one-ticket scope.
